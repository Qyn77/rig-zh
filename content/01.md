# 安装

Rig 以 crates.io 上的 `rig` crate 发布。本页介绍如何添加依赖、设置服务商 API Key，以及通过 Cargo feature 选择集成、传输层和 TLS。配置完成后，前往[快速入门](/docs/quickstart)构建第一个 Agent。

@@ANCHOR:prerequisites@@

## 前置条件

- **Rust 1.97.1 或更新版本。** 使用 [rustup](https://www.rust-lang.org/tools/install) 安装，并通过 `rustup update` 更新。
- **模型服务商的 API Key。** 本文档的示例使用 OpenAI，并读取 `OPENAI_API_KEY`。其他服务商使用各自的变量，例如 `ANTHROPIC_API_KEY`、`GEMINI_API_KEY` 或 `COHERE_API_KEY`。通过 [Ollama](https://ollama.com) 使用本地模型不需要 Key。

## 各个 crate 如何配合

`rig` 是门面 crate，大多数应用只需依赖它。

- **`rig-core`** 包含可移植的接口约定：消息、服务商客户端与模型、工具、嵌入、记忆以及向量存储 trait。
- **`rig-agent`** 是 Agent 运行时，提供 `AgentBuilder`、工具调用循环、钩子、数据提取和可逐步推进的运行状态。门面默认通过 `agent` feature 启用它。
- **各项集成**（向量存储、额外服务商、MCP、录制）位于独立 crate，门面通过 feature 控制的模块暴露它们。例如，启用 `qdrant` feature 后可使用 `rig::qdrant`。

完整介绍见[架构](/docs/architecture)。

@@ANCHOR:cargo-features@@

## Cargo feature

默认启用 `agent`、`derive`、`reqwest` 和 `rustls`，分别提供 Agent 运行时、派生宏（`#[derive(Embed)]`、`#[rig::rig_tool]`）、内置 HTTP 传输层和 rustls TLS 实现。

@@ANCHOR:webassembly@@

## WebAssembly

Rig 无需额外 feature 即可编译到 `wasm32-unknown-unknown`（浏览器）；目标平台会自动选择兼容 wasm 的代码路径。在 wasm 下：

- `rig-core` 和 Agent 运行时均可工作，reqwest 传输层使用浏览器的 `fetch`。
- MCP 工具（`rmcp`）和内置 WebSocket 后端仅支持原生平台。
- 不支持 WASI 目标（`wasm32-wasip1`、`wasm32-wasip2`）。

@@ANCHOR:using-rig-core-directly@@

## 直接使用 rig-core

如果只需要服务商接口，并准备编写自己的 Agent 循环，可以依赖 `rig-core`，而非门面 crate。它没有默认传输层：启用其 `reqwest` feature 可使用内置 HTTP 客户端，也可通过 配置的 `connect` 传入自己的客户端。其余文档均使用 `rig` 门面。
