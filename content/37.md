# OpenAI

OpenAI 服务商模块（`rig::providers::openai`）涵盖 OpenAI 的补全、嵌入、转录、图像和语音模型。其客户端 `OpenAI` 也供 Rig 支持的所有 OpenAI 兼容服务商使用（DeepSeek、Groq、OpenRouter、Together 等），各家通过自己的模块完成配置。

@@ANCHOR:capabilities@@

## 支持的能力

| 能力 | 支持情况 | 使用方式 |
| --- | --- | --- |
| 补全 | 支持 | `client.completion(id)`（Responses API）、`client.chat(id)`（Chat Completions） |
| 流式输出 | 支持 | `agent.prompt(p).stream()` 或 `model.stream(request)` |
| 工具 | 支持 | 任意 Rig 工具 |
| 结构化输出 | 支持 | 原生 JSON Schema 输出，由提取器和 `output_schema` 使用 |
| 图像输入 | 支持 | 具备视觉能力的模型 |
| 推理 | 支持 | `GenerationOptions::reasoning`；通过 `OpenAiOptions` 获取摘要 |
| 嵌入 | 支持 | `client.embedding(id, None)` |
| 转录 | 支持 | `client.transcription(openai::WHISPER_1)` |
| 图像生成 | `image` feature | `client.image_generation(openai::GPT_IMAGE_2)` |
| 语音 | `audio` feature | `client.audio_generation(openai::TTS_1)` |
| Websocket 会话 | `websocket` feature | `model.responses_websocket().connect()` |

## Responses 与 Chat Completions

OpenAI 提供两套补全 API，Rig 为每套都提供了对应模型：

- `client.completion(id)` 创建服务商的主要端点。对 OpenAI 来说是 **Responses API**（`POST /responses`）。
- `client.responses(id)` 始终创建 Responses 模型。
- `client.chat(id)` 始终创建 **Chat Completions** 模型（`POST /chat/completions`）。

请求发送前，每个选项都会根据模型进行检查。OpenAI 自动缓存提示词；对允许选择缓存时长的模型，`CacheRetention` 决定保留多久。如果模型不接受某个选项（例如不支持某档推理强度），会返回 `ProviderError::UnsupportedOption`，而不是静默丢弃。调用 `.on_unsupported(OnUnsupported::Ignore)` 可以改为跳过不支持的选项并发出警告。

@@ANCHOR:openai-only-options@@

## OpenAI 专有选项

OpenAI 独有的字段在 `openai::extension` 中提供类型定义。`OpenAiOptions` 分为三部分：两套 API 共有的字段（`store`、`metadata`、`prompt_cache_key`、`safety_identifier`），Responses 专有字段（`reasoning_summary`、`include`、`conversation`、`truncation`、`background`、`max_tool_calls` 等），以及 `ChatOptions` 中的 Chat 专有字段（`logit_bias`、`prediction`、`logprobs`、惩罚参数、音频输出、网页搜索选项）。每部分只会发送给对应 API。

## 工具

OpenAI 模型可以调用你注册到 Agent 上的任意工具。对两套 API，Rig 都会把工具定义转换为 OpenAI 函数格式，并把工具调用解析回自身类型。见[工具](/docs/concepts/tools)。
