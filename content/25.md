# 构建 RAG 系统

检索增强生成（RAG）让语言模型依据你的数据作答：收到问题后，先从知识库检索最相关的段落，再把这些段落和问题一起交给模型。模型根据上下文回答，不再仅依赖训练时记住的知识，从而减少幻觉，并能使用最新、私有或特定领域的信息。

本指南用不到 100 行代码构建完整 RAG 系统：从 PDF 提取文本，逐页生成嵌入，将向量存入内存，再把存储作为动态上下文接入 Agent。关于嵌入、相似度搜索、重排序和工具 RAG 等概念，见[向量存储与 RAG](/docs/concepts/rag)。

## 生成文档嵌入并建立存储

创建嵌入模型，用 `EmbeddingsBuilder` 为每页生成嵌入，再把结果放入 `InMemoryVectorStore`。内存存储适合中小规模文档集；更大的语料库可换用 [LanceDB、MongoDB、Neo4j 或 Qdrant](/docs/integrations/vector_stores) 等持久化存储。

@@CODE_004@@

`EmbeddingsBuilder::new(model).documents(pages)?` 将页面加入待嵌入队列；`.build().await?` 分批调用嵌入 API。`InMemoryVectorStore::from_documents_with_id_f` 直接根据这些嵌入建立存储，以每页的 `id` 作为存储中的 ID。现在嵌入文档和之后嵌入查询使用同一个模型；模型克隆成本低。`.erase()` 将具体类型的模型转换为与服务商无关的 `DynModel`，让后续代码不必写出 OpenAI 模型类型。

说明

向现有存储添加更多向量时，调用 `vector_store.add_documents(embeddings)`。它按值接收嵌入，不是异步方法。

## 用于生产环境

- **持久化存储**：大规模文档集应将 `InMemoryVectorStore` 替换为专门的[向量存储](/docs/integrations/vector_stores)，例如 LanceDB、MongoDB、Neo4j 或 Qdrant，只需生成一次嵌入，而不是每次启动都重新生成。
- **分块**：按页分块简单直接；内容密集的文档可进一步拆成相互重叠的段落。见[加载器](/docs/concepts/loaders)。
- **模型选择**：在答案质量允许时，使用成本更低的补全模型。
- **可观测性**：Rig 可与 OpenTelemetry 和 Langfuse 集成，见[可观测性](/docs/concepts/observability)。
