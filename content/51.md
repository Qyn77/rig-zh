# 参与贡献

Rig 是开源项目，欢迎社区贡献代码、文档或反馈。本页介绍最需要帮助的方向。仓库中的 [CONTRIBUTING.md](https://github.com/0xPlaygrounds/rig/blob/main/CONTRIBUTING.md) 提供了拉取请求、提交消息和本地检查的完整规范。

注意

**开始开发新功能或修改之前**，先搜索已有的 [issue 和拉取请求](https://github.com/0xPlaygrounds/rig/issues)，在想接手的条目下留言；如果没有对应条目，就新建 issue。较大的 API 或架构变更应先讨论。

## 仓库结构

Rig 是一个 monorepo。根包是 `rig` 统一入口；`crates/rig-core` 包含跨平台接口约定和内置服务商；`crates/rig-agent` 包含 Agent 运行时；其他每个 `crates/rig-*` crate 是带较重依赖的集成（向量存储、依赖 SDK 的服务商、MCP、记录）。统一入口将每个配套 crate 暴露为由 feature 控制的模块。

## 开发

@@ANCHOR:model-provider-integrations@@

### 模型服务商集成

如果 Rig 尚未支持你喜欢的模型服务商，可以考虑添加。

- 内置服务商位于 [`crates/rig-core/src/providers`](https://github.com/0xPlaygrounds/rig/tree/main/crates/rig-core/src/providers) 下各自的模块中。
- 如果服务商提供 **OpenAI 兼容 API**，通常无需新建 wire：添加一种协议变体（dialect，描述基础 URL、凭证环境变量和特殊行为），再仿照 `deepseek` 等现有模块添加包含 `from_env()`、`new()` 构造函数的小型服务商模块。
- 需要厂商 SDK 或其他较重依赖的服务商，应放入独立配套 crate，例如 `rig-bedrock` 或 `rig-vertexai`。
- 服务商行为变更应附带基于 cassette 的回归测试，通过离线重放已记录的服务商流量验证。

注意

内置服务商集成不应给 `rig-core` 添加新依赖。

@@ANCHOR:vector-store-integrations@@

### 向量存储集成

如果 Rig 尚未支持你喜欢的向量存储，可以考虑添加。

- 每种向量存储都有独立的 `crates/rig-<store>` crate，例如 [`rig-qdrant`](https://github.com/0xPlaygrounds/rig/tree/main/crates/rig-qdrant)，因为存储通常带来较大的客户端依赖。
- 实现用于搜索的 `VectorStoreIndex` 和用于写入的 `InsertDocuments`，并将 crate 注册为统一入口的 feature，使用户可通过 `rig::<store>` 访问。
- 参照现有存储添加集成测试。

@@ANCHOR:bug-fixes@@

### 修复缺陷

如果发现缺陷，请提交附带可复现示例的 [issue](https://github.com/0xPlaygrounds/rig/issues)，也欢迎提交修复问题并附带测试的拉取请求。

## 文档

@@ANCHOR:guides-and-tutorials@@

### 指南与教程

如果你有 Rig 使用经验并愿意分享，可以编写指南或教程。要将它发布到本网站，请向[网站仓库](https://github.com/0xPlaygrounds/rig-site)提交拉取请求。

@@ANCHOR:other-documentation-improvements@@

### 其他文档改进

如果发现拼写错误、内容错误，或某个章节可以写得更清楚，请向[网站仓库](https://github.com/0xPlaygrounds/rig-site)提交 issue 或拉取请求。其 README 说明了如何在本地运行网站。文档中的每个 Rust 代码片段都会在 CI 中针对当前 Rig 版本编译，因此你添加的代码必须能够构建。

## 想法与反馈

如果你有功能想法，或对现有功能的反馈，请在 [GitHub 仓库](https://github.com/0xPlaygrounds/rig/issues)提交 issue。先检查已有 issue，避免重复提出已经规划或正在开发的内容。
