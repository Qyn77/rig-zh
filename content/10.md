# 持久化运行

每次 Agent 运行的底层都有 `AgentRun`：一个可序列化的状态机，记录提问、历史、轮数预算和下一步操作。它自身不执行 I/O，不持有模型、工具、记忆或钩子，而是告诉**驱动器**该做什么，由驱动器把结果传回来。`agent.prompt(..)` 就是一种这样的驱动器：[`AgentRunner`](/docs/concepts/agentrunner) 替你逐步推进 `AgentRun`，在过程中调用模型、执行工具和[钩子](/docs/concepts/hooks)。

当一次运行需要**跨越启动它的任务的生命周期**时，就自行推进 `AgentRun`。步骤之间，整个运行都支持 `Serialize + Deserialize`，因此可以在等待工具调用时停下，将运行写入数据库或文件，再于数小时后在另一个进程中接续，例如等到人工批准调用之后。

你需要它吗？

如果审批可以在运行等待期间完成，例如策略检查或同一进程中的交互提示，`on_dispatch` 钩子更简单，参见[工具调用：审批与防护规则](/docs/concepts/hooks#tool-calls-approvals-and-guardrails)。当决策需要跨越重启或在别处完成时，再使用 `AgentRun`。

## 逐步执行协议

用 `AgentRun::new(prompt)` 创建运行，用 `.max_turns(n)` 设置预算，用 `.with_history(..)` 设置之前的消息，然后在循环中调用 `next_step()`。每一步都是以下三种情况之一：

| 步骤 | 驱动器应执行的操作 |
| --- | --- |
| `AgentRunStep::CallModel { prompt, history, turn }` | 发送补全请求，并把响应传给 `run.model_response(..)`。 |
| `AgentRunStep::CallTools { calls }` | 匹配 `PendingToolCall`，通过 `call.answer(..)` 构造回答，交给 `run.answer(..)` 或 `answer_all(..)`。 |
| `AgentRunStep::Done(response)` | 停止：`response` 与等待 Agent 完成时返回的 `PromptResponse` 相同。 |

`model_response` 返回 `ModelTurnOutcome`。`NeedsResolution(context)` 表示模型调用了不能调用的工具；此时使用 `run.resolve_invalid_tool_call(action)` 回答，动作值与钩子返回的 `InvalidToolCallAction` 相同。运行会自行约束轮数预算和协议顺序：轮数耗尽返回 `PromptError::MaxTurns`，以错误顺序调用方法，或回答并非待处理状态的工具调用，都会返回错误。

## 暂停以等待审批

下面的程序在模型想调用工具时停下，把运行保存到文件，再加载回来并请人逐一批准调用。工具只模拟转账，不连接银行、不移动资金。传入 `--offline` 使用 Mock 模型，可不带密钥验证审批和恢复；输入 `y` 执行一次模拟，其他输入拒绝。保存和加载之间的操作可以发生在另一个进程、Web 请求处理器中，甚至隔到第二天：重新加载的运行完全依据已保存状态，重新发出待处理调用。

@@CODE_000@@

驱动器必须遵循几条规则：

- 每个待处理调用恰好回答一次，顺序不限。拒绝调用时，用说明拒绝原因的工具结果回答；模型能读到它并调整。编辑调用时，使用不同参数执行工具。中止时，直接停止推进运行即可。
- `PendingToolCall::Execute(call)` 才能执行；`Malformed(call)` 用 `call.answer(None)` 生成默认反馈。已经回答的调用不会在恢复后重新发出，未知变体应停止或报错，不能猜测执行。
- 自行调用模型时，请求也由你构建。运行提供提问和历史；系统提示词、工具与采样设置由驱动器提供。用与该请求一致的 `TurnPolicy` 构造 `ModelTurn::from_policy`，或用完整的 `PreparedRequest` 构造 `ModelTurn::from_response`，让运行能区分有效和无效调用。

Rig 的 `agent_run_stepping` 和 `agent_with_durable_approval` 示例提供了这个循环的完整可运行版本，包括编辑和中止选项。

## 交给 Agent 恢复执行

你不必手动将持久化运行驱动到底。`agent.resume(run)` 返回 `AgentRunner`，用 Agent 的模型、工具、钩子和请求设置继续执行：先执行待处理的工具调用，再继续循环。你可以像其他运行一样对它使用 `.await` 或 `.stream()`。

@@CODE_001@@

已保存的内容以运行自身为准，包括提问、历史、轮数预算和无效工具调用设置，因此在恢复后的 runner 上调用 `history(..)` 和 `max_turns(..)` 不会生效。恢复的运行不加载也不保存对话记忆；你需要自行将 `response.messages` 追加到存储中。

## 持久化状态

- **格式**：序列化的运行会记录格式版本（`rig::run::RUN_FORMAT`，0.46.0 为 `5`）。反序列化会明确拒绝其他版本或未知字段，不会猜测兼容方式。恢复时应使用保存它时相同的 Rig 版本。旧格式的待审批运行应在旧版本完成，不能直接当作格式 5 加载。
- **你自己的记录**：用 `run.append_entry(Aside::new(kind, author, value))` 在运行中保存审批决定或工单 ID 等宿主数据；`Aside` 来自 `rig::conversation`。`entries_of(kind)` / `last_entry_of(kind)` 可以读回。条目绝不会发送给模型。`Aside` 可以关联消息 ID，并保存作者信息；它不再使用旧 `RunEntry` 的 `turn` 字段。钩子通过 `HookContext::append_entry` 和 `entries` 读写同一批条目，因此恢复运行后的钩子能看到暂停前发生的事情。
- **不包含的内容**：模型、工具、钩子、记忆后端和工具上下文。恢复时要重新创建它们。不要把机密写入条目，因为运行状态可能被存储在任何地方。
