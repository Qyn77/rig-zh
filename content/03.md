# 架构

Rig 将**基础接口**（模型、工具、向量存储等）与**执行流程**（调用这些接口的 Agent 循环）分开。基础接口可用于不同平台，Agent 运行时负责协调调用。`rig` crate 是二者的统一入口，因此大多数应用只需依赖 `rig`，无需直接引用底层 crate。本页介绍它们的关系。

## 各个 crate

**`rig`** 是统一入口。它通过常用路径重新导出 `rig-core`（`rig::completion`、`rig::providers`、`rig::embeddings`、`rig::vector_store` 等），通过 `rig::agent` 和 prelude 提供 Agent 运行时，并将各项集成放在由同名 Cargo feature 控制的模块中。

**`rig-core`** 包含其他 crate 赖以构建的可移植接口约定：

- 服务商客户端及其构建的模型（`Model`、`DynModel`）
- 消息、补全请求与响应、类型化生成选项
- 工具定义与 `Tool` trait
- 嵌入、对话记忆 trait、向量存储 trait，以及内存向量存储
- 流式事件、错误类型、遥测和文件加载器

**`rig-agent`** 提供 Agent 运行时，由统一入口的 `agent` feature 默认启用。它包含 `AgentBuilder`、`Agent`、工具调用循环、类型化钩子、实时工具注册表、数据提取，以及可序列化状态机 `AgentRun`。后者决定循环中的每一步，但自身不执行 I/O。

**配套 crate** 提供带有较重依赖的集成：向量存储（`rig-qdrant`、`rig-lancedb`、`rig-mongodb` 等）、额外服务商（`rig-bedrock`、`rig-vertexai`、`rig-gemini-grpc`、`rig-candle`）、本地嵌入（`rig-fastembed`）、MCP 工具（`rig-rmcp`）、记忆策略（`rig-memory`）以及调用记录与重放（`rig-cassette`）。通过统一入口可以用 `rig::<name>` 访问：

## 核心抽象

各部分自底向上组合：服务商客户端构建模型，Agent 包装模型，你的代码驱动 Agent。[快速入门](/docs/quickstart)用一个完整程序展示这条调用链。

@@ANCHOR:provider-clients@@

### 服务商客户端

每个服务商的客户端类型（`OpenAI`、`Anthropic`、`Gemini`、`Ollama` 等）保存配置（凭证、基础 URL）和传输层，通过 `from_env()` 或 `new(api_key)` 创建。使用其他服务商协议格式的服务，如兼容 OpenAI 格式的 DeepSeek 或 Groq，提供 `deepseek::from_env()` 这样的模块级构造函数。

参见[服务商与客户端](/docs/concepts/provider_clients)。

@@ANCHOR:models@@

### 模型

客户端通过 `client.completion(id)`、`client.embedding(id, None)` 等方法构建模型；服务商支持时，还能构建转写、图像生成和音频生成模型。`Model` 将 **协议适配器 wire**（如何编码某个服务商端点的请求、解码响应）与**传输层**（如何传输字节）配对。`call` 发送一次请求并返回统一格式的响应，`stream` 则随响应到达逐步返回内容。`DynModel` 隐藏了具体的服务商类型（类型擦除），让不同服务商的模型可以用同一种类型保存和传递。

参见[模型生成](/docs/concepts/completion)和[向量嵌入](/docs/concepts/embeddings)。

@@ANCHOR:agents@@

### Agent

`Agent` 将模型、系统提示词、工具、动态上下文、记忆和钩子组合起来，并负责执行循环：调用模型、运行模型请求的工具、回传结果，重复此过程，直到模型给出答案或达到调用次数预算。每次提问都返回 `AgentRunner`，可在 `.await` 或 `.stream()` 前配置本次运行的历史、预算、钩子和模型。

底层循环的决策位于 `AgentRun` 中。你也可以手动推进它，在步骤之间持久化，并在其他位置恢复。

参见 [Agent](/docs/concepts/agent)、[AgentRunner](/docs/concepts/agentrunner)、[钩子](/docs/concepts/hooks)、[工具](/docs/concepts/tools)和[可持久化运行](/docs/concepts/runs)。

@@ANCHOR:vector-stores@@

### 向量存储

检索依靠两个 trait：`InsertDocuments` 添加已生成嵌入的文档，`VectorStoreIndex` 执行相似度搜索。内存存储随 `rig-core` 提供，配套 crate 则为外部数据库实现相同的 trait。任何索引都能为 Agent 提供动态上下文，也可以作为工具暴露。

参见[向量存储与 RAG](/docs/concepts/rag)和[向量存储集成](/docs/integrations/vector_stores)。

@@ANCHOR:workflows@@

### 工作流

用普通 Rust 将模型、Agent 和工具组合成多步流程：顺序调用、使用 `futures::join!` 并发执行，或用 `match` 分支。不需要工作流 DSL。

参见[工作流](/docs/concepts/chains)。

## 支持的平台

| 目标 | 状态 |
| --- | --- |
| 原生平台（Linux、macOS、Windows；x86_64 和 aarch64） | 完整支持，包含所有 feature |
| `wasm32-unknown-unknown`（浏览器） | 无需 feature 标记即可使用；MCP（`rmcp`）和内置 WebSocket 后端不可用 |
| WASI（`wasm32-wasip1`、`wasm32-wasip2`） | 不支持 |
