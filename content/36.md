# 模型服务商

模型服务商是提供补全、嵌入或其他模型的服务（或本地运行时），例如 OpenAI、Anthropic、Gemini、Ollama。Rig 为每家提供结构相同的小型客户端，因此切换服务商通常只需修改导入和模型 ID。

@@ANCHOR:vocabulary@@

## 术语

- **服务商模块**：`rig::providers::<name>`，包含该服务商的客户端、模型 ID 常量和类型化选项。
- **配置**：服务商设置，包括 API Key、基础 URL、API 版本，例如 `openai::OpenAIConfig` 或 `anthropic::AnthropicConfig`。配置是可序列化的普通数据；密钥原值不会被序列化，`Secret` 会输出 `[redacted]` 占位符。
- **客户端**：绑定到 HTTP 传输层的配置，例如 `openai::OpenAI` 或 `anthropic::Anthropic`。客户端克隆成本低，可用于创建模型。
- **模型**：`Model<W>` 将 *wire*（发送什么、如何解析回复）与客户端的传输层组合起来。通过 `client.completion(id)` 或 `client.embedding(id, None)` 等方法取得模型，再交给 `AgentBuilder::new`、`EmbeddingsBuilder::new`、向量存储等。如果需要用同一种类型表示多个服务商，调用 `model.erase()` 可将其转换为 `DynModel`。

调用链始终是：**客户端 → 模型 → Agent／提取器／索引**。

这些类型如何融入 Rig 的其他部分，见[服务商与客户端](/docs/concepts/provider_clients)。

## 创建客户端

所有内置客户端都有相同的构造方式：`from_env()?` 读取服务商的环境变量，缺失时返回指出变量名的 `EnvError`；`new(key)` 接收明确给出的密钥；`OpenAIConfig::new(key).with_base_url(..).client()` 这类配置方式支持密钥以外的设置。配置的 `.connect(http)` 可替换 HTTP 传输层。兼容 OpenAI 的服务商（DeepSeek、Groq、Together、OpenRouter 等）没有独立的客户端类型：其模块中的 `from_env()` 和 `new(key)` 返回为该服务商配置好的 `OpenAI` 客户端，例如 `deepseek::from_env()?`。

[服务商与客户端](/docs/concepts/provider_clients)介绍了这些构造方式、自定义传输层，以及如何在运行时根据配置数据选择服务商（`Catalog::builtin().connect("deepseek/deepseek-v4-flash")`）。

这些服务商位于 `rig::providers`，无需额外 feature。

| --- | --- | --- |
| [OpenAI](/docs/integrations/model_providers/openai) | `openai::OpenAI::from_env()?`（`OPENAI_API_KEY`） | `completion` 使用 Responses API；还提供 `chat`、`embedding`、`transcription`、`image_generation`（`image` feature）、`audio_generation`（`audio` feature）和 Responses websocket 会话（`websocket` feature）。 |
| [Anthropic](/docs/integrations/model_providers/anthropic) | `anthropic::Anthropic::from_env()?`（`ANTHROPIC_API_KEY`） | Messages API：工具、扩展思考、提示词缓存。不提供嵌入。 |
| Azure OpenAI | `azure::from_env()?`（`AZURE_ENDPOINT`、`AZURE_API_VERSION`、`AZURE_API_KEY` 或 `AZURE_TOKEN`） | 模型 ID 是你的部署名称。 |
| ChatGPT（订阅） | `chatgpt::from_env()?`（`CHATGPT_ACCESS_TOKEN`） | 使用 Responses 格式；通过 `chatgpt::auth::Authenticator` 和 `OpenAI::authenticate` 登录。 |
| Cohere | `cohere::Cohere::from_env()?`（`COHERE_API_KEY`） | 通过 Cohere 的 OpenAI 兼容 API 聊天，或用 `cohere::ChatRoute` 选择其原生 API（文档依据、引用）。支持文本和图像嵌入。 |

| DeepSeek | `deepseek::from_env()?`（`DEEPSEEK_API_KEY`） | 兼容 OpenAI。 |

| OpenRouter | `openrouter::from_env()?`（`OPENROUTER_API_KEY`） | 路由偏好、回退设置和回复费用在 `openrouter::extension` 中。 |
| Perplexity | `perplexity::from_env()?`（`PERPLEXITY_API_KEY`） | 兼容 OpenAI 的 Sonar 模型。 |

对 OpenAI 风格的客户端，`completion(id)` 创建服务商的主要端点：OpenAI、xAI 和 ChatGPT 使用 Responses API，其余使用 Chat Completions。`chat(id)` 和 `responses(id)` 可明确指定其中一种。

## 服务商专有选项

可移植选项（推理强度、提示词缓存保留时间、服务等级、`top_p`、停止序列等）是 `rig::completion::GenerationOptions` 的字段，各服务商将其映射到自身的请求字段。如果模型不支持某个选项，请求会以 `ProviderError::UnsupportedOption` 失败，除非设置 `.on_unsupported(OnUnsupported::Ignore)`。仅某一家支持的字段位于其 `extension` 模块中（`openai::extension::OpenAiOptions`、`anthropic::extension::AnthropicOptions`、`openrouter::extension::OpenRouterOptions` 等），通过 `.provider_option(options)` 附加。参见[生成选项](/docs/concepts/completion#generation-options)和[服务商扩展](/docs/concepts/completion#provider-extensions)；[OpenAI](/docs/integrations/model_providers/openai)和 [Anthropic](/docs/integrations/model_providers/anthropic) 页面介绍了各自的字段。
