# 测试

测试 Rig Agent 时，可以传入**模拟模型（Mock）**，用预先设定的响应代替真实模型调用。这样无需调用模型服务商，也不会产生模型费用，便于重复验证 Agent 的行为。Mock 只替代模型；工具和其他依赖仍可能执行真实操作，完整离线测试需要同时使用本地依赖或测试替身。Mock 类型位于 `rig::test_utils`，由 `test-utils` feature 启用。

## 模拟模型响应

`MockCompletionModel::text(...)` 返回一个模型，它会用给定文本回答一次。在它之上创建普通 Agent，并像平常一样提问即可，无需 API Key。

@@CODE_002@@

每个预设轮次只使用一次。如果 Agent 调用模型的次数超过预设，额外的调用会返回服务商错误，因此测试不会靠重复使用同一答案悄悄通过。

## 预设多轮工具循环

真实 Agent 会循环执行：模型请求工具，Rig 执行工具，模型再根据结果回答。用 `MockTurn` 预设每个模型轮次：`MockTurn::tool_call(id, name, args)` 表示工具请求，`MockTurn::text(...)` 表示最终答案。`MockCompletionModel` 的克隆共享状态，因此可以保留一份供事后检查。

@@CODE_003@@

`MockTurn::error(...)` 预设一次服务商失败，用于测试错误处理和重试。对于流式 Agent，使用 `MockCompletionModel::from_stream_turns` 和 `MockStreamEvent` 预设各数据块。

## 重放已记录的调用

Mock 适合测试自己的程序逻辑。如果想用真实模型曾经返回的结果做回归测试，可以先记录一次在线调用，再在 CI 中重放。见[调用记录与重放](/docs/concepts/recording)。

说明

Mock 测试应聚焦自己的代码：工具接入、提示词构建、检索和错误处理。真实模型能否给出高质量答案，应通过记录运行和人工评审判断，而不是通过预设答案的 Mock。
