# 常见问题

常见问题的简短回答。涉及概念时，可继续阅读链接中的详细说明。

@@ANCHOR:what-is-rig@@

## Rig 是什么？

Rig 是一个开源 Rust 库，用于构建大语言模型驱动的应用：它提供跨服务商的统一 API，以及 Agent、工具、RAG、结构化提取等高层构件。从[简介](/docs)和[快速开始](/docs/quickstart)入手。

@@ANCHOR:should-i-depend-on-rig-rig-core-or-rig-agent@@

## 应该依赖 `rig`、`rig-core`，还是 `rig-agent`？

依赖 `rig`。它重新导出 `rig-core`（服务商、模型、工具和向量存储契约）与 `rig-agent`（默认启用的 Agent 运行时），并通过 Cargo feature 暴露集成。只有在你需要服务商契约，但不需要 Agent 运行时或门面集成时，才直接依赖 `rig-core`。见[架构](/docs/architecture)。

@@ANCHOR:which-model-providers-does-rig-support@@

## Rig 支持哪些模型服务商？

统一 API 支持 20 多家服务商，包括 OpenAI、Anthropic、Google Gemini、Cohere、Mistral、xAI、DeepSeek、Groq、OpenRouter、Perplexity、Together、Azure OpenAI、Hugging Face 和 Ollama；还通过由 feature 控制的配套 crate 支持 Amazon Bedrock 和 Google Vertex AI。见[服务商与客户端](/docs/concepts/provider_clients)和[模型服务商](/docs/integrations/model_providers)。

@@ANCHOR:can-i-run-local-or-self-hosted-models@@

## 可以运行本地或自行托管的模型吗？

可以。使用 Ollama 或 llama.cpp 客户端访问本地服务器，将 `OpenAIConfig::with_base_url` 指向任意 OpenAI 兼容端点，或启用 `candle` feature 在进程内运行支持的模型。见[服务商与客户端](/docs/concepts/provider_clients#any-other-openai-compatible-server)。

@@ANCHOR:do-i-have-to-use-tokio@@

## 必须使用 Tokio 吗？

示例使用 `#[tokio::main]`，但 Rig 并不要求 Tokio。内置 HTTP 传输层会自行带上所需依赖；Agent 运行只是一个普通 future，可以由任意执行器驱动。

@@ANCHOR:does-rig-work-in-the-browser@@

## Rig 能在浏览器中运行吗？

可以。Rig 无需额外 feature 就能为 `wasm32-unknown-unknown` 构建。MCP 工具和内置 websocket 后端仅支持原生目标平台，不支持 WASI 目标。见[安装](/docs/installation#webassembly)。

@@ANCHOR:does-rig-support-fine-tuning@@

## Rig 支持微调吗？

不支持。Rig 专注于推理和编排，不负责训练。使用服务商的工具完成微调，再像其他模型一样，将生成的模型 ID 交给 Rig。

@@ANCHOR:how-do-i-continue-a-conversation@@

## 如何继续一段对话？

在提示词上通过 `.history(&history)` 传入之前的消息，再追加本次运行的新消息：`history.extend(response.messages)`。如果希望对话自行加载和保存，接入记忆后端。见 [Agent](/docs/concepts/agent) 和[记忆](/docs/concepts/memory)。

@@ANCHOR:how-do-i-set-reasoning-effort-prompt-caching-or-other-provider-settings@@

## 如何设置推理强度、提示词缓存或其他服务商设置？

通用设置是类型化、可移植的：在 `CompletionRequest`、`AgentBuilder` 或单次运行上使用 `.reasoning(Effort::High)`、`.cache(CacheRetention::Long)`、`.service_tier(..)`、`.seed(..)` 等。服务商专有设置使用 `rig::providers::<name>::extension` 中的类型化选项，通过 `.provider_option(..)` 传入；`additional_params` 仍可接收原始 JSON。见[补全](/docs/concepts/completion#generation-options)。

@@ANCHOR:how-does-rig-handle-rate-limits-and-retries@@

## Rig 如何处理限流和重试？

Rig 不会自行重试服务商调用。`ProviderError::is_retryable()` 告诉你故障是否是暂时性的，因此可以在调用外层实现带退避的重试；也可以将 `reqwest-middleware` 客户端传给 配置的 `connect`，在 HTTP 层重试，或通过 Agent 钩子重试一个模型轮次。类型化提取有独立的 `.retries(n)`，用于重试无法解析的回答。见[错误处理](/docs/concepts/error_handling)。

@@ANCHOR:can-i-use-rig-in-a-web-service@@

## 能在 Web 服务中使用 Rig 吗？

可以。Rig 是异步的，适合 Axum、Actix 等 Web 框架，也适合无服务器平台。见[指南](/docs/guides)，其中包含 AWS Lambda 部署教程。

@@ANCHOR:can-i-test-without-calling-a-real-model@@

## 能不调用真实模型就进行测试吗？

可以。`test-utils` feature 提供可按轮次编排响应的模拟模型；`cassette` feature 可以录制真实运行并离线回放。见[测试](/docs/concepts/testing)。

@@ANCHOR:how-does-rig-compare-to-other-llm-frameworks@@

## Rig 与其他 LLM 框架相比如何？

Rig 提供你预期的构件（Agent、工具、RAG、结构化提取），同时具备 Rust 的性能、类型安全，以及跨服务商统一 API。各部分如何组合，见[架构](/docs/architecture)。
