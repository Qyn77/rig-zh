# 错误处理

Rig 中每个可能失败的调用都返回类型化错误，让你根据失败*原因*作出处理，而不是解析字符串。两种类型覆盖了绝大多数情况：

- **`PromptError`**：Agent 运行失败，例如 `agent.prompt(..).await`，或 `.stream()` 的最后一项。
- **`ProviderError`**：调用服务商失败，包括补全、嵌入、转写、图片生成和模型列表。所有操作共用一种类型，用不同变体说明失败原因。

要求返回指定 Rust 类型的提问（`prompt_typed`）和提取器会将 `PromptError` 包装在 `StructuredOutputError` 中，见[结构化输出](/docs/concepts/extractors)；向量存储返回 `VectorStoreError`。

## Agent 运行错误

`agent.prompt(..).await` 返回 `Result<PromptResponse, PromptError>`。`PromptError` 标记为 `#[non_exhaustive]`，因此 `match` 必须有兜底分支：

@@CODE_000@@

| 变体 | 含义 |
| --- | --- |
| `Provider(ProviderError)` | 模型调用失败：网络错误、限流、无效请求、无法解析的响应，或服务商以错误结束了轮次。 |
| `Report(ErrorReport)` | 以序列化报告形式传递的失败，例如来自 hook、调用处理器（handler），或转发的流。字段与下文相同。 |
| `Memory(MemoryError)` | [对话记忆](/docs/concepts/memory)加载或保存历史失败。 |
| `MaxTurns { max_turns, chat_history, prompt }` | 运行用完了全部模型调用预算。通过 `.max_turns(n)` 或 `.default_max_turns(n)` 提高预算。 |
| `Cancelled { reason, chat_history }` | Hook 停止了运行。 |
| `UnknownToolCall { tool_name, available_tools, allowed_tools, .. }` | 模型调用了 Agent 在当前轮次未提供的工具，且没有 hook 恢复该错误。 |

中途终止运行的变体会携带 `chat_history`，即失败前的对话，可用于记录日志或继续运行。

工具返回错误**不会**产生 `PromptError`：错误会作为工具结果交回模型，运行继续。见[工具失败时](/docs/concepts/tools#when-a-tool-fails)。不过，hook 仍可在特定工具失败时结束运行，此时表现为 `Cancelled`。

提示

`MaxTurns` 表示模型调用次数达到上限。可能是上限不足以完成正常的多步任务，也可能是模型反复调用工具。同一次模型响应可以请求多个工具，`max_turns` 统计模型调用轮数，不是工具数量。应为多步任务留出足够轮数，并提供清楚的工具错误信息，帮助模型调整下一步操作。见[工具](/docs/concepts/tools)。

## 服务商错误

直接调用模型（`model.call(..)`、`model.stream(..)`、`embedding_model.embed_text(..)`）会返回 [`ProviderError`](https://docs.rs/rig/0.46.0/rig/error/enum.ProviderError.html)，`PromptError::Provider` 包装的也是它。主要变体如下：

| 变体 | 含义 |
| --- | --- |
| `Http(..)` | 未收到响应的传输失败：连接重置、超时、响应不可读。 |
| `ProviderResponse(ProviderResponseError)` | 服务商返回错误：非 2xx 状态，或 2xx 状态但响应体为错误。原响应会保留。 |
| `InvalidAuthentication(ProviderResponseError)` | 服务商拒绝凭证（401 或 403）。 |
| `Json(..)` | 请求或响应无法序列化或反序列化。 |
| `Request(..)` | 无法构建请求。 |
| `UnsupportedOption(..)` | 请求设置了模型或 API 无法满足的选项，例如推理、缓存。默认 `OnUnsupported::Error` 策略会报错；`OnUnsupported::Ignore` 则跳过该选项。 |
| `Response(String)` | 响应已解码，但没有回答请求，或服务商以错误结束轮次。 |
| `Truncated` | 服务商尚未完成响应就中断，例如流在响应中途断开。 |

`ProviderError` 同样标记为 `#[non_exhaustive]`。无需匹配每个变体，可使用辅助方法：

- `error.is_retryable()`：相同请求再次发送是否可能成功。传输失败、超时、HTTP 408/429/5xx 和截断响应可重试；无效请求、凭证被拒及格式错误的响应不可重试。
- `error.kind()`：返回 [`ErrorKind`](https://docs.rs/rig/0.46.0/rig/error/enum.ErrorKind.html)，所有操作使用相同分类。
- `error.provider_response()`：以 [`ProviderResponseError`](https://docs.rs/rig/0.46.0/rig/struct.ProviderResponseError.html) 返回保留的响应，包含 `status`、原始 `body`、`headers` 和 `provider_request_id`。各字段也有便捷访问方法：`provider_response_status()`、`provider_response_body()`、`provider_response_json()`、`provider_response_headers()` 和 `provider_request_id()`。

`PromptError` 转发了相同的 `provider_response_*` 访问方法，无需先解包变体就能读取服务商响应。

## 未知结束原因会导致运行失败

每个模型响应都带有结束原因。Rig 接受正常原因，例如停止、工具调用、token 达到上限。若结束原因不在这些范围内，本轮以 `PromptError::Provider(ProviderError::Response(..))` 失败，其中的工具调用不会执行，因为这类原因通常说明响应有问题，例如 Gemini 的 `MALFORMED_FUNCTION_CALL` 或 Bedrock 的 `malformed_tool_use`。内容过滤导致的停止也会使本轮失败。
