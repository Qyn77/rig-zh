# 调用记录与重放

`cassette` 用于保存 Agent 的调用过程，方便测试和复现问题。它记录通过 Rig 分派的模型调用、工具调用、向量检索等操作（effect），包括请求及其结果，形成调用日志（effect log）。重放时，Agent 的流程会重新执行，但这些调用由日志提供结果，不再访问对应的服务商或执行原来的工具。

例如，天气助手先让模型选择天气工具，再查询天气，最后生成回答。记录一次真实运行后，测试就可以用保存的模型响应和天气查询结果重复执行这段流程，无需再次调用这两个服务。

**适用范围**：日志只替代已记录并接入重放处理器的调用，不是整个程序的快照。Hook、记忆存储以及应用自身的代码仍可能执行 I/O。只有这些部分也使用本地状态或测试替身时，整个测试才能离线运行；重放不会自动回滚存储，也不能保证任意代码都产生相同结果。

主要用途：

- **用真实模型结果做回归测试。** 在线记录一次，再在 CI 中重放。与[模拟模型（Mock）](/docs/concepts/testing)不同，重放使用的响应来自真实调用，而不是手工设定。
- **发现调用变化。** 默认会比较当前请求与已记录的请求。提示词或工具参数发生变化时，重放会在出现差异的调用处报错。
- **复现线上问题。** 保存发生问题时的调用日志，在本地检查执行过程；运行依赖的其他状态仍需另行准备。

## 重放一次运行

先读取日志，用 `register_all` 将重放处理器注册到 `Handlers`，再通过 `AgentBuilder::over_handlers` 构建 Agent。这样，模型请求就会交给日志处理器。示例从记录中取得模型 key，并使用与记录时相同的 owner 和提示词。

**0.46.0 适配说明**：官方旧示例使用 `Bus::channel()` 和 `over_bus`。本页已改为 `Handlers` 和 `over_handlers`；处理器由当前异步任务驱动，不需要额外启动总线任务。

@@CODE_002@@

`register_all` 默认按请求内容进行比较（`RequestCheck::Payload`），忽略新会话生成的工具调用 ID、提示词缓存键等特定字段。提示词或工具参数等内容不匹配，或日志中没有对应记录时，会报告重放差异，不会改为请求真实模型。API 也提供跳过请求比较的模式，但该模式不能用来证明请求与原来一致。

如果还要检查 Agent 的配置哈希、钩子列表和所需处理器，应在执行前主动调用 `agent.check_replayable(&log)`（需导入 `AgentReplayExt`）。它与逐次请求比较是两项不同的检查；仅调用 `register_all` 不会替你完成 Agent 配置与钩子列表的比对。

## 记录哪些内容

记录范围是经过 Rig 调用处理器分派的操作，包括模型响应及其流、工具调用，以及 `dynamic_context` 和检索工具触发的向量检索。它不是对进程内所有网络、文件和数据库操作的自动监控。

**0.46.0 适配说明**：官方旧版正文把记忆读写也列为 effect。当前版本的记忆读写属于 `Store` / `AsyncStore` 存储操作，不包含在这类调用重放中。测试需要自行准备相应的对话状态，重放不会替你模拟或回滚存储。

Hook 的执行不由日志替代：重放时它们会再次运行。日志头会记录钩子列表，显式调用 `check_replayable` 时会检查是否匹配；这不代表 Hook 内部的任意逻辑或外部依赖都已被验证。

调用日志带有格式与配置兼容性信息。Rig 升级后，旧日志可能不再适用；检查失败时应在对应版本重新记录。将日志当作生成文件，不要为了让测试通过而手工篡改。
