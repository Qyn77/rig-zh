# 录制与回放

一次 Agent 运行是一系列 effect（外部效果）：模型调用、工具调用、向量搜索。Rig 可以把每个 effect 的请求及结果录入 **effect 日志**。之后回放日志时，Agent 会再次运行，但每个 effect 都由日志回答，不再请求服务商或执行工具。无需 API Key、无需联网，每次得到相同答案。

用途包括：

- **基于真实模型输出测试。** 录制一次在线运行，提交日志，再在 CI 中回放。与 [Mock](/docs/concepts/testing) 不同，模型的回答来自真实调用。
- **发现意外变化。** 回放会检查 Agent 的请求是否与录制时相同。提示词或工具参数改变时，回放在产生差异的 effect 处失败。
- **调试生产运行。** 保存出错运行的日志，在本地逐步检查。

## 录制一次运行

创建 `EffectLogRecorder`，保留其句柄，并通过 `AgentBuilder::record_to` 将一个克隆交给 Agent。运行结束后，`recorder.take()` 返回日志；`agent.stamp(log)` 将 Agent 的身份信息（配置与 hook 栈的哈希）写入日志头，供回放时核对。`EffectLog` 是普通 serde 数据，可以用任意方式保存。

@@CODE_001@@

`recorder.log()` 返回快照，但不清空录制器。如果需要保留流式响应的确切数据块，而不只是最终结果，请用 `EffectLogRecorder::keeping_stream_events()` 代替 `new()`。

## 回放一次运行

回放时，把日志的回放器注册到 `Handlers`，再用 `AgentBuilder::over_handlers` 构建 Agent。处理器在当前 future/stream 内执行，无需总线驱动任务或 `tokio::spawn(driver)`。模型 key 从补全记录中取得；录制与回放保持相同的 owner 和提示词。

@@CODE_002@@

回放会逐一比较 Agent 发出的请求与录制请求。两者不同，例如提示词或系统提示词发生变化时，运行会失败，错误会指出哪个 effect 出现分歧；它不会猜测答案。`agent.check_replayable(&log)` 在分派任何 effect 之前，预先检查日志头中的配置哈希、hook 栈和必需的处理器。

## 录制哪些内容

Agent 分派的每个 effect 都会录制：补全调用及其流、工具调用，以及 `dynamic_context` 和检索工具产生的向量存储检索。记忆读写属于 `Store` / `AsyncStore` 操作，不再属于 effect；回放不会替你模拟或回滚存储。Hook 不会录制，回放时会再次运行。这也是日志头记录 hook 栈、且回放拒绝不同 hook 栈的原因。

日志与写入它的 Rig 版本绑定。若 Agent 配置格式改变，`check_replayable` 会拒绝旧日志，需要重新录制。应把日志当作生成文件；不要为了让测试通过而手工修改，应重新录制。
