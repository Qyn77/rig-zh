# 模型生成（Completion）

Completion 通常译为“补全”，这里指让模型根据输入生成响应：发送一次请求，接收文本、工具调用等结果，不是编辑器里的代码自动补全。它是 [Agent](/docs/concepts/agent) 使用的底层模型接口，本身不负责工具循环、对话记忆或 Agent 钩子。需要直接控制模型请求或自行编写循环时，就使用这一层。

开始之前

- 按[服务商与客户端](/docs/concepts/provider_clients)创建客户端和模型。
- 大多数应用应从 [Agent](/docs/concepts/agent) 开始，由它构建这些请求。

## 构建请求

`CompletionRequest::new(prompt)` 创建一个以该提示词为最后一条消息的对话。其他内容通过设置方法添加：

| 设置方法 | 设置的内容 |
| --- | --- |
| `.preamble(text)` | 位于开头的系统消息 |
| `.messages(history)` / `.message(m)` | 插在提示词之前的历史轮次 |
| `.documents(docs)` / `.document(d)` | 上下文文档 |
| `.tools(defs)` / `.tool(def)` | 模型可调用的工具定义 |
| `.tool_choice(choice)` | 模型必须、可以或不得调用工具 |
| `.output_schema(schema)` | 回答应遵循的 JSON Schema |
| `.temperature(t)` / `.max_tokens(n)` | 采样温度和输出 token 上限 |
| `.model(id)` | 仅本次请求改用的模型 ID |
| `.additional_params(json)` | 合并进服务商请求体的原始 JSON |

@@ANCHOR:generation-options@@

## 生成选项

不同服务商命名不同的设置，例如推理强度、提示词缓存、服务等级，都有可移植的类型化接口。将它们设置到请求上，各服务商会映射为自己的 JSON 格式：

@@CODE_002@@

| 选项 | 可用值 |
| --- | --- |
| `reasoning` | `Effort::{Minimal, Low, Medium, High, XHigh, Max}`、`Reasoning::Budget { tokens }` 或 `Reasoning::Off` |
| `cache` | `CacheRetention::{None, Short, Long}`：服务商保留提示词前缀缓存的时间 |
| `service_tier` | `ServiceTier::{Auto, Default, Flex, Priority}` |
| `verbosity` | `Verbosity::{Low, Medium, High}` |
| `parallel_tool_calls`、`top_p`、`seed`、`stop` | 常用采样与工具设置 |

服务商不会默默丢弃选项。若服务商或模型无法满足某项设置，会在发送之前返回 `ProviderError::UnsupportedOption`。添加 `.on_unsupported(OnUnsupported::Ignore)` 后，不支持的选项会被跳过并产生警告。未设置选项的请求按构建时的内容发送。

`GenerationOptions` 将这些设置集中为一个可复用值，可通过 `.options(..)` 传给请求。`AgentBuilder` 也提供相同设置方法，让它们应用于 Agent 的每次模型调用。

@@ANCHOR:responses@@

## 响应

所有服务商的 `CompletionResponse` 都使用相同结构：

| 字段或方法 | 内容 |
| --- | --- |
| `choice` | `Vec<AssistantContent>`；每个输出项对应一个块，按服务商返回顺序排列，也可能为空 |
| `text()` / `reasoning()` | 拼接后的文本块或推理块 |
| `tool_calls()` | 模型请求的工具调用 |
| `message()` | 将响应转为助手 `Message`，可直接追加到历史 |
| `usage` | token 计数，见下文 |
| `finish_reason()` | 模型停止的原因 |
| `provider()`、`model()`、`response_id()` | 响应来源 |
| `raw` | 服务商原始 JSON 响应文档 |

`AssistantContent` 包含 `Text`、`ToolCall`、`Reasoning`、`Image` 和 `Opaque`（Rig 保留的服务商专有内容项；其中的 `replay` 标记决定是否在后续对话中将它再次发送给原模型，并非 cassette 的离线重放）。该枚举标记为 `#[non_exhaustive]`，所以 `match` 必须包含 `_` 分支。

@@ANCHOR:finish-reasons@@

### 结束原因

`finish_reason()` 返回统一的 `FinishReason`：`Stop`、`Length`、`ToolCalls`、`ContentFilter`；不在这些类别中的服务商原始值用 `Other(raw)` 表示。

@@CODE_004@@

Agent 会将未知原因（`Other`）、内容被过滤或服务商报告失败视为失败轮次，而非正常回答。若想接受服务商在标准集合之外返回的原因，可在请求或 Agent 上设置 `.accept_unknown_finish_reasons(true)`。

@@ANCHOR:token-usage@@

### Token 用量

`Usage` 的每项计数都是 `Option<u64>`，以区分“未报告”和零：`input_tokens`、`output_tokens`、`total_tokens`、`cached_input_tokens`、`cache_creation_input_tokens`、`tool_use_prompt_tokens`、`reasoning_tokens`。服务商报告费用时，`cost` 保存一个 `Cost`。

@@CODE_005@@

Agent 运行会累加每次模型调用的用量，可从最终 `PromptResponse` 的 `usage` 字段读取。[模型目录](/docs/concepts/provider_clients#listing-models-and-checking-credentials)可为已知模型的 `Usage` 计算费用。

@@ANCHOR:messages@@

## 消息

一个对话是 `Vec<Message>`：

- `Message::System { content }`：系统指令，通过 `Message::system(text)` 构建。
- `Message::User { content }`：`UserContent` 块列表，可包含文本、图像、音频、视频、文档或工具结果。`Message::user(text)` 构建纯文本消息。
- `Message::Assistant(AssistantMessage)`：模型返回的内容块，以及来源和轮次结束信息。可通过 `Message::assistant(text)` 手动构建。

@@ANCHOR:errors@@

## 错误

调用失败时返回 `ProviderError`。其变体区分传输失败（`Http`）、响应格式错误（`Json`、`Response`）、服务商报告的错误（`ProviderResponse`、`InvalidAuthentication`）和被拒绝的选项（`UnsupportedOption`）。`is_retryable()` 用于区分临时与永久错误。参见[错误处理](/docs/concepts/error_handling)。
