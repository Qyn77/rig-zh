# 向量存储

向量存储同时保存文档及其嵌入，并返回与查询最相似的文档。在 Rig 中，它是 [RAG](/docs/concepts/rag) 背后的存储层：为数据生成一次嵌入，写入存储，然后在发送提示词时查询。

每种集成都实现相同的两个 trait，因此无论使用内置内存存储，还是 Qdrant、MongoDB、LanceDB 等数据库，插入和查询文档的代码几乎相同。本页介绍这些共通部分，各存储页面介绍具体配置。

在类型上派生 `Embed`，用 `#[embed]` 标记需要嵌入的一个或多个字段。`EmbeddingsBuilder` 会批量执行嵌入调用：

@@CODE_001@@

`build()` 返回每个文档及其配对的 `Vec<Embedding>`。一个文档可以携带多个嵌入（每个 `#[embed]` 字段条目一个，或每个分块一个），存储按其中最佳匹配进行排名。使用 `.document(doc)?` 可以每次添加一个文档。

写入和查询存储应使用同一个嵌入模型。存储的向量维度（如果有此设置）必须与模型一致：`model.capabilities().ndims`。

`Embed` 派生宏和嵌入模型的说明见[向量嵌入](/docs/concepts/embeddings)。

## 使用 VectorSearchRequest 查询

每次查询都是一个 `VectorSearchRequest`：包含查询文本、结果数量（`samples`）、用于丢弃弱匹配的可选 `threshold`，以及可选元数据 `filter`。[直接搜索索引](/docs/concepts/rag#searching-an-index-directly)展示了完整查询及其结果。

阈值如何比较取决于后端采用的度量方式；各存储页面会说明差异。默认过滤器类型 `rig::vector_store::request::Filter` 与后端无关，也是内存存储使用的类型。数据库存储有自己的过滤器类型，它们提供相同的 `SearchFilter` 方法（`eq`、`gt`、`lt`、`and`、`or`），并增加后端专用方法，例如 `QdrantFilter`、`LanceDBFilter`（SQL 谓词）和 `MongoDbSearchFilter`。在请求上指定类型，例如 `VectorSearchRequest::<QdrantFilter>::builder()`；通用 `Filter` 可通过 `filter.interpret()` 转换为后端过滤器。

@@ANCHOR:errors@@

## 错误

存储操作返回 `VectorStoreError`：`EmbeddingError`（嵌入调用失败）、`JsonError`（文档序列化或反序列化失败）、`DatastoreError`（后端失败）、`FilterError`（过滤器构建或转换失败）、`MissingIdError`、`SamplesOutOfRange`，以及通过 HTTP 访问存储时的 `Http`／`ExternalAPIError`。

## 集成

内存存储内置于 `rig`。其他存储都是配套 crate，通过 `rig` 上的 feature 启用，再通过同名模块访问：

@@CODE_005@@

| 存储 | Feature | 主要类型 | 说明 |
| --- | --- | --- | --- |
| [内存存储](/docs/integrations/vector_stores/in_memory) | 无 | `InMemoryVectorStore`、`InMemoryVectorIndex` | 仅在 RAM 中；暴力搜索或 LSH。适合开发、测试和小数据集。 |
| [LanceDB](/docs/integrations/vector_stores/lancedb) | `lancedb` | `rig::lancedb::LanceDbVectorIndex` | 嵌入式列式存储，位于本地磁盘或 S3/GCS/Azure；精确搜索或 IVF-PQ 搜索。 |
| [MongoDB](/docs/integrations/vector_stores/mongodb) | `mongodb` | `rig::mongodb::MongoDbVectorIndex` | Atlas Vector Search。 |
| [Neo4j](/docs/integrations/vector_stores/neo4j) | `neo4j` | `rig::neo4j::Neo4jClient`、`Neo4jVectorIndex` | 与图数据放在一起的向量索引。 |
| [Qdrant](/docs/integrations/vector_stores/qdrant) | `qdrant` | `rig::qdrant::QdrantVectorStore` | 专用向量数据库。 |
| [SurrealDB](/docs/integrations/vector_stores/surrealdb) | `surrealdb` | `rig::surrealdb::SurrealVectorStore` | 内存或远程 SurrealDB。 |
| SQLite | `sqlite` | `rig::sqlite::SqliteVectorStore`、`SqliteVectorIndex` | 通过 `sqlite-vec` 扩展使用单文件存储；用 `SqliteVectorStoreTable` 描述表。 |
| PostgreSQL | `postgres` | `rig::postgres::PostgresVectorStore` | `pgvector` 列，可选择距离函数。 |
| Milvus | `milvus` | `rig::milvus::MilvusVectorStore` | Milvus v2 HTTP API。 |
| ScyllaDB | `scylladb` | `rig::scylladb::ScyllaDbVectorStore` | 在 ScyllaDB 中存储向量，在你的进程中计算得分。 |
| HelixDB | `helixdb` | `rig::helixdb::HelixDBVectorStore` | 通过 HelixDB HTTP 客户端访问。 |
| AWS S3 Vectors | `s3vectors` | `rig::s3vectors::S3VectorsVectorStore` | 接收你的 AWS SDK 客户端。 |
| Cloudflare Vectorize | `vectorize` | `rig::vectorize::VectorizeVectorStore` | 通过 Cloudflare HTTP API 访问。 |

如果希望嵌入处理始终留在本机，启用 `fastembed` feature 即可使用 `rig::fastembed`，其本地嵌入模型可配合上述任意存储。见[本地模型](/docs/integrations/model_providers/local_models#local-embeddings-with-fastembed)。
