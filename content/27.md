# 模型路由

模型路由决定由哪个模型回答请求。Rig 支持三个层面的路由：

- **在多个 Agent 之间**：低成本分类器或嵌入搜索选出一个专门的 Agent，再由它回答。
- **在单个 Agent 内部**：Agent 用标签持有多个模型，hook 在每次模型调用之前选择标签。例如用快模型规划和调用工具，用更强的模型撰写最终答案。
- **从配置创建**：配置文件或用户设置中的字符串，例如 `"anthropic/claude-sonnet-5-5"`，在运行时转换为模型。

三者都基于同一个事实：`Agent` 不以服务商作为泛型参数。所有模型都以 `impl Into<DynModel<Completion>>` 接收，因此不同服务商的 Agent 和模型共享同一种类型，可以存进同一个 `HashMap`、`Vec` 或结构体字段。

## 在单个 Agent 内路由模型

在多个 Agent 之间路由，是为整个请求选定一个 Agent。有时应当为每次模型调用分别选择：在使用工具的运行中，决定调用什么工具的请求可以交给快模型，撰写最终答案的请求交给更强模型。Agent 可以为此持有多个模型：

- `AgentBuilder::new(model)` 将 `model` 注册到 `default` 标签下；`AgentBuilder::named_model(label, model)` 则用你指定的标签注册。
- `.model_route(label, model)` 注册另一个运行时可选择的模型。
- 带有 `on_model_select` 的 `AgentHook` 在每次模型调用前执行，返回 `ModelSelectionAction::select(label)`、`::continue_run()`（保留当前候选）或 `::stop(reason)`（在调用前结束运行）。

这些模型可以来自不同服务商。历史以 Rig 的服务商中立格式保存，因此一个模型发出的工具调用，可以由另一个模型接收结果并继续处理。

@@CODE_003@@

Hook 收到的 `ModelSelection` 描述待执行调用：将发送的 `prompt` 和 `history`、运行的 `default_model`、前面 hook 选择的 `selected_model`，以及上次调用使用的 `previous_model`。因此路由可以依赖对话内容，而不只是轮次编号。接口约定如下：

- 通过 `AgentBuilder::add_hook` 添加的 hook 作用于该 Agent 的每次运行；在提示词上添加的 hook（`agent.prompt(p).add_hook(h)`）只作用于本次运行。
- 多个选择 hook 按注册顺序执行，每个都能看到前一个的选择；最后一次选择生效，停止决定会结束运行。
- 每次模型调用前都会重新选择，包括重试和工具结果后的调用，因此运行可以中途换模型；已发出的调用不会切换。
- 选择未注册的标签会导致运行失败。

[`runtime_model_routing`](https://github.com/0xPlaygrounds/rig/blob/v0.46.0/crates/rig-agent/examples/runtime_model_routing.rs) 示例用预设模型完整演示双模型的工具往返，无需 API Key。
