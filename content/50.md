## 运行时未设置 API Key

@@CODE_004@@

**原因：** `from_env()` 从环境读取服务商密钥，缺失时返回错误。代码可以正常编译，故障发生在运行时。

**修复：** 运行前导出密钥，或加载 `.env` 文件。各服务商的环境变量见[服务商与客户端](/docs/concepts/provider_clients)。

@@CODE_005@@

@@ANCHOR:reached-the-max-turns-limit-of-1@@

## 报 `reached the max turns limit of 1`

**原因：** 默认情况下，Agent 每次提示词只调用模型一次。调用工具后再回答至少需要两次：一次请求工具，一次根据工具结果回答。

**修复：** 在 Agent 或单次提示词上提高预算。预算表示本次运行允许的模型调用总次数。

@@CODE_006@@

@@ANCHOR:my-tool-is-never-called@@

## 工具始终没有被调用

**原因：** 模型根据工具的**名称和描述**决定何时调用。元数据含糊，或存在太多功能重叠的工具，都会让模型跳过它。

**修复：** 给工具明确的 `NAME`，并在 `description()` 中准确说明使用时机；保持工具集精简、功能不重叠。确保轮次预算为工具调用留出空间（见上文）。用[模拟模型](/docs/concepts/testing)预设各轮响应和工具调用，检查工具是否正确接入。

@@ANCHOR:structured-output-fails-to-deserialize@@

## 结构化输出反序列化失败

**原因：** 模型返回的 JSON 与你的类型不匹配。错误为 `StructuredOutputError::Deserialization`，其中保留模型原始 `output`，可供检查。通常是 schema 有歧义，或某个字段描述不清。

**修复：** 让字段能够说明自身含义（文档注释会变成 schema 描述），对模型可能省略的值使用 `Option<T>`，对固定选项使用 `enum`，防止模型编造取值。见[结构化输出](/docs/concepts/extractors)。

@@ANCHOR:-is-not-supported-by--model-before-the-request-is-sent@@

## 请求发送前报 `... is not supported by ... model`

@@CODE_007@@

**原因：** 你设置了所选服务商或模型不支持的生成选项（推理、缓存、服务等级等）或服务商选项。Rig 会拒绝请求，而不是静默丢弃该选项。

**修复：** 为该模型移除对应选项，或添加 `.on_unsupported(OnUnsupported::Ignore)`，跳过不支持的选项并发出警告。见[模型生成](/docs/concepts/completion#generation-options)。

@@ANCHOR:the-run-fails-on-an-unknown-finish-reason@@

## 运行因未知结束原因而失败

**原因：** 服务商以 Rig 规范化集合之外的结束原因终止了该轮，或过滤了内容。Agent 会将这一轮视为失败，避免返回可能不完整的答案。

**修复：** 如果该服务商的额外结束原因在你的用途下属于正常情况，可在 Agent 构建器、提示词或请求上设置 `.accept_unknown_finish_reasons(true)`，明确接受它们。
