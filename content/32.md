# 编写自己的服务商

Rig 内置[许多服务商](/docs/integrations/model_providers)，你也可以在 Rig 仓库之外添加自己的实现。本指南按工作量由小到大介绍三种方式：

1. 服务商使用 **OpenAI Chat Completions** 格式：声明一个 dialect（协议变体）。
2. 服务商使用 **Anthropic Messages** 格式：声明一个 Messages dialect。
3. 服务商有**自己的 API**：为它编写 wire（协议适配器）。

@@ANCHOR:how-a-rig-model-is-built@@

## Rig 模型如何构成

Rig 中的每个模型都是 `rig::driver::Model<W, T>`，组合了两部分：

- **Wire**（`W: rig::wire::Wire`）：描述一个端点的普通数据，负责把请求编码成 HTTP 请求，并提供响应解码器。它不接触网络。
- **Transport**（`T: rig::driver::Transport<W>`）：负责请求如何传输。任何实现 `HttpClientExt` 的 HTTP 客户端都是 transport，因此大多数 wire 无需指定它。默认使用共享的 reqwest 客户端。

Driver 位于两者之间，负责其余事项：发送请求、将响应拆成帧（SSE、NDJSON 或完整响应体）、状态检查、遥测，以及把解码事件归并成 `CompletionResponse`。单次响应（`model.call`）和流式响应（`model.stream`）经过**同一个解码器**，因此服务商只需实现一次，就能支持两种方式。同一模型也能用于 Agent（`AgentBuilder::new(model)`）、包装成 `DynModel`，并兼容 Agent 运行时中的所有 hook 和工具。

`OpenAI` 这样的服务商客户端只是便利封装：配置加 transport，以及 `completion(model)` 等返回 `Model` 的方法。

### 配置与 wire

Wire 是普通数据，应实现 `Clone`，通常还实现 `Debug`、`PartialEq`、`Serialize` 和 `Deserialize`，以便像其他配置一样保存和加载。凭证应保存在 `rig::wire::Secret` 中；它在打印和序列化时显示为 `[redacted]`，防止 Key 进入日志。

@@ANCHOR:replay-target@@

### Replay target

每个补全 wire 都实现 `ReplayTarget`。编码器运行前，Rig 用它把对话整理成适合该模型的形式。模型不能读取的内容会降级：图片变成占位符；`tools` 关闭时，工具调用与结果转换成文本。这样，其他任何服务商产生的历史都能发送给你的服务商，而编码器只会收到你声明支持的内容。

`map_options` 说明请求中的每个通用选项（`top_p`、`seed`、`stop`、推理等）如何发送。解构 `fields` 时不要使用 `..`，这样 Rig 新增选项后，你必须处理它才能通过编译。`Mapping::Send` 将 JSON 合并到请求体；`Mapping::unsupported` 在发送前拒绝该选项。

@@CODE_005@@

0.46.0 的 `OptionFields` / `OptionMap` 包含 `cache_key`。示例使用 `Mapping::unrouted(cache_key)` 明确处理未映射选项。

`ReplayTarget` 还提供一些带默认实现的方法，供规则更严格的服务商使用，例如 `starts_with_user`、`alternates_roles` 和 `normalize_tool_call_id`。按你的 API 要求覆盖相应方法即可。

@@ANCHOR:decoder@@

### 解码器

解码器读取一次响应。`classify` 把帧解析为你的类型化事件。对于 JSON 帧，使用 `rig::providers::internal::wire` 中的共享分类器，以便将无效 JSON 报告为损坏响应，而不是静默跳过。`decode` 通过 `Out` 将事件写入响应：

- `out.run(Block::Text, text)` 追加文本。连续的同类内容会合并为一个块。
- `out.end(Finish { .. })` 用用量、结束原因、响应 ID 和模型信息结束响应。若所有帧耗尽仍未结束，会报告响应被截断。

@@CODE_006@@

解码器无需知道响应是否来自流。单次响应时，完整响应体就是一帧；流式响应时，每行 NDJSON 是一帧。

### Wire

`Wire` 实现指定操作（`Completion`）、载荷（`Encoded`，包含 HTTP 请求及拆分响应的方式）、帧类型、解码器和重组器。`describe` 为遥测提供服务商名与模型名，并指向 replay target。

`encode` 不得执行任何 I/O。在闭包中构建你自己的请求体，再传给 `options::request_params`。它会按照所有内置服务商相同的顺序，依次加入映射后的选项、类型化服务商选项，以及调用方的 `additional_params`。

@@CODE_008@@

`Wire::Event` 与解码器事件类型一致；这里为 `Chunk`。`chat_history` 内的消息由 `Arc` 持有，匹配时使用 `message.as_ref()`。

服务器发送事件流使用 `Framing::Sse`。如果服务商在响应头返回请求 ID，用 `Encoded::with_request_id_header` 指定 header 名称，Rig 就会将其附到响应和错误上。

@@ANCHOR:other-operations@@

## 其他操作

补全只是一种操作。嵌入、重排序、转写、图片和音频生成（`rig::operation::{Embedding, Rerank, Transcription, ImageGeneration, AudioGeneration}`）遵循同样方式：一个 `Op` 为对应操作的 wire，加一个响应解码器。可参考匹配的内置 wire，例如 `openai::wire::Embeddings`。

如果端点不属于任何现有操作，可定义自己的 `rig::wire::Operation`，包含请求、响应和 fold（归并器）。当响应是单个 JSON 文档时，现成的 `Json` 解码器和 `Whole` fold 可以完成工作。Rig 的 [`frozen_api` 示例](https://github.com/0xPlaygrounds/rig/tree/v0.46.0/examples/frozen_api) 展示了这种方式（`p6_http_operation.rs`），以及自定义 OpenAI dialect（`p7_openai_compatible_vendor.rs`）和回放 transport（`p8_custom_transport.rs`）。
