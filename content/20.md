# 可观测性

可观测性是指：不必到处添加调试代码，也能从外部了解应用正在做什么。对 LLM 应用而言，这一点尤其重要。模型具有非确定性，因此需要跟踪 token 用量、延迟、错误和工具调用，才能有把握地运行行为不可完全预测的系统。

开始之前

- 构建并运行一个 [Agent](/docs/concepts/agent)；Agent 运行和模型调用都会产生 span（追踪跨度）。
- 配置服务商客户端，例如 [OpenAI](/docs/concepts/provider_clients)，让示例有实际可追踪的调用。

Rig 通过 [`tracing`](https://docs.rs/tracing) crate 发出遥测数据。你可以用任意 [`tracing-subscriber`](https://docs.rs/tracing-subscriber) 层、日志门面或 OpenTelemetry 导出器接收；Rig 本身不会安装这些组件。

## Rig 发出哪些数据

Rig 的 span 遵循 [OpenTelemetry GenAI 语义约定](https://opentelemetry.io/docs/specs/semconv/gen-ai/)，因此 [Langfuse](https://langfuse.com/) 和 [Arize Phoenix](https://phoenix.arize.com/) 等支持 GenAI 的后端无需额外映射就能理解这些数据。

| Span | 产生时机 | 关键属性 |
| --- | --- | --- |
| `invoke_agent` | 一次 Agent 运行（`agent.prompt(..)`），覆盖其中所有轮次 | `gen_ai.agent.name`、累计 `gen_ai.usage.*` |
| `chat` | 一次模型调用（Gemini 使用 `generate_content`） | `gen_ai.provider.name`、`gen_ai.request.model`、`gen_ai.response.model`、`gen_ai.response.id`、`gen_ai.request.stream`、`gen_ai.usage.input_tokens`、`gen_ai.usage.output_tokens`，以及缓存和推理 token 数 |
| `execute_tool` | 一次工具调用 | `gen_ai.tool.name`、`gen_ai.tool.call.id`、`gen_ai.tool.call.outcome`、`gen_ai.tool.error.type` |
| `embeddings`、`rerank`、`transcription`、`image_generation`、`audio_generation` | 一次相应类型的模型调用 | 服务商、模型及用量 |

模型调用 span 嵌套在 Agent span 下，工具 span 嵌套在发起它的轮次下。如果在你自己的 span 内调用 `agent.prompt(..)`，Rig 会将这个 span 用作 Agent span，而不是新建一个 `invoke_agent` 根 span。

## 故障排查

- **Span 顺序不正确。** 操作在大约一毫秒内完成时，例如一个很快的工具，某些后端会因时间戳精度而把 span 显示成轻微乱序。实际工作负载很少遇到。
- **Span 中没有内容。** 默认关闭内容记录，见[记录消息内容](#recording-message-content)。
