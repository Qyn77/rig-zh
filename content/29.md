# 构建 Discord 机器人

本教程用 [Rig](https://github.com/0xPlaygrounds/rig) 和 [Serenity](https://docs.rs/serenity/) Discord 库构建机器人。机器人通过检索增强生成（RAG），依据 Markdown 知识库回答问题：每次提问时，Rig 为查询生成嵌入，从向量存储取出最接近的文档，再把文档和问题一起交给模型。

实现分为两部分：

1. **Rig Agent**（`rig_agent.rs`）：加载 Markdown 文件、生成嵌入并构建 RAG [`Agent`](/docs/concepts/agent)。这一部分没有 Discord 代码，可以独立测试。
2. **Discord 层**（`main.rs`）：注册 `/ask` 斜杠命令、监听提及机器人，并把两种请求都转交 Agent。

如果不熟悉 Rig 中的 RAG，先浏览[向量存储与 RAG](/docs/concepts/rag)和[构建 RAG 系统](/docs/guides/rag/rag_system)指南。

## Rig Agent（rig_agent.rs）

`build_agent` 读取目录中的每个 Markdown 文件，使用 OpenAI 的 `text-embedding-3-small` 分别生成嵌入，存入内存向量存储，然后创建一个 Agent，在每次提问时将最接近的两份文档加入上下文。

@@CODE_004@@

- `client.embedding(model, None)` 创建嵌入模型；`None` 保留模型默认的向量维度。
- `EmbeddingsBuilder` 为每份文档生成嵌入。`String` 直接嵌入其自身内容；结构化文档则派生 `Embed`，并标记需要嵌入的字段，见[向量嵌入](/docs/concepts/embeddings)。
- `dynamic_context(2, index)` 将检索变成 Agent 的组成部分：每次模型调用之前，用提示词搜索 `index`，将前两份文档加入请求。

`Agent` 克隆成本低，可安全地跨任务共享，Discord 处理器依赖这一点。

## 运行与测试

@@CODE_007@@

日志打印 `<bot name> is connected` 后，将机器人邀请进服务器：

1. 在 [Discord Developer Portal](https://discord.com/developers/applications) 打开应用，进入 **OAuth2 → URL Generator**。
2. 在 **Scopes** 下选择 `bot` 和 `applications.commands`。
3. 在 **Bot Permissions** 下选择 `Send Messages` 和 `Read Message History`。
4. 打开生成的 URL，选择你的服务器。

然后试试：

- `/ask query: How do I get started?`
- `@YourBot what does the FAQ say about pricing?`

## 故障排查

- **机器人从不响应提及**：Message Content intent 未开启。在 Developer Portal 中启用，并在 `main` 中保留 `GatewayIntents::MESSAGE_CONTENT`。
- **`/ask` 显示“The application did not respond”**：模型调用之前没有延迟回复确认，确保第一步执行 `command.defer`。
- **`reading documents` 错误**：从项目根目录运行机器人，或给 `build_agent` 传绝对路径。
