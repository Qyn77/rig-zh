# 生态集成

Rig 通过**模型服务商**（LLM 和嵌入 API）、**向量存储**（用于语义搜索和 RAG 的数据库），以及 MCP 工具、记录等其他集成连接外部系统。轻量集成随 `rig-core` 提供；依赖较重的集成放在配套 crate 中，由 `rig` 统一入口通过同名 Cargo feature 暴露为模块：

## 模型服务商

内置服务商客户端是各家 HTTP API 的轻量封装。它们随 `rig-core` 提供，无需额外 feature：

@@CODE_001@@

| 类型 | 服务商 |
| --- | --- |
| 使用自有 API 格式 | OpenAI、Anthropic、Google Gemini、Cohere、Ollama、Voyage AI（嵌入和重排序）、GitHub Copilot |
| 兼容 OpenAI | Azure OpenAI、DeepSeek、Doubleword、Groq、Hugging Face、Hyperbolic、llama.cpp、MiniMax、Mira、Mistral、Moonshot、OpenRouter、Perplexity、Together AI、Venice、xAI、Xiaomi MiMo、Z.AI、ChatGPT（订阅账号登录） |

需要 SDK 或本地运行的服务商由配套 crate 提供：

| 服务商 | Feature | 模块 |
| --- | --- | --- |
| Amazon Bedrock | `bedrock` | `rig::bedrock` |
| Google Vertex AI | `vertexai` | `rig::vertexai` |
| 通过 gRPC 访问 Google Gemini | `gemini-grpc` | `rig::gemini_grpc` |
| Candle（本地 CPU 推理：Llama、SmolLM2、Qwen3） | `candle` | `rig::candle` |
| FastEmbed（本地嵌入） | `fastembed` | `rig::fastembed` |

客户端的创建方式见[服务商与客户端](/docs/concepts/provider_clients)，各服务商的独立说明见[模型服务商](/docs/integrations/model_providers)。

## 向量存储

每种存储都实现 `rig-core` 中相同的 trait：`VectorStoreIndex` 用于相似度搜索，`InsertDocuments` 用于写入。因此，无论底层使用哪个数据库，RAG 流水线和动态上下文 Agent 的工作方式都一样。`rig-core` 自带内存存储 `InMemoryVectorStore`，适合原型和测试。

| 存储 | Feature | 模块 |
| --- | --- | --- |
| HelixDB | `helixdb` | `rig::helixdb` |
| LanceDB | `lancedb` | `rig::lancedb` |
| Milvus | `milvus` | `rig::milvus` |
| MongoDB Atlas | `mongodb` | `rig::mongodb` |
| Neo4j | `neo4j` | `rig::neo4j` |
| PostgreSQL（pgvector） | `postgres` | `rig::postgres` |
| Qdrant | `qdrant` | `rig::qdrant` |
| Amazon S3 Vectors | `s3vectors` | `rig::s3vectors` |
| ScyllaDB | `scylladb` | `rig::scylladb` |
| SQLite（sqlite-vec） | `sqlite` | `rig::sqlite` |
| SurrealDB | `surrealdb` | `rig::surrealdb` |
| Cloudflare Vectorize | `vectorize` | `rig::vectorize` |

共同概念和各存储的说明见[向量存储](/docs/integrations/vector_stores)。
