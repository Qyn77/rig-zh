# 将 Rig 部署到 AWS Lambda

使用 Rig 构建的 Rust Agent 会编译成单个小型二进制文件，内存占用低、冷启动快，很适合 AWS Lambda。本指南用 [`cargo lambda`](https://www.cargo-lambda.info/guide/getting-started.html) CLI，将一个调用 OpenAI API、不使用向量存储的简单 Rig Agent 部署到 Lambda，再分析云端指标。

作为参考，我们将部署后的 Rig Agent 与同平台上功能相当的 Python Agent 比较。概括如下：

- 内存占用更低，约 26MB 对约 130MB。
- 冷启动更快，约 90ms 对约 1900ms。
- 在不同内存配置下，性能更一致。

## AWS Lambda 概览

如果 Rust 应用的任务能在 15 分钟内完成，或应用是 REST API 后端，可以考虑部署到 AWS Lambda。

@@ANCHOR:aws-and-rust@@

### AWS 与 Rust

AWS Lambda 通过 [Amazon Linux 2023 OS-only runtime](https://docs.aws.amazon.com/lambda/latest/dg/lambda-runtimes.html)，配合 [Rust runtime client](https://github.com/awslabs/aws-lambda-rust-runtime) crate，支持 Rust。

@@ANCHOR:rest-api-backend@@

#### REST API 后端

- 使用 runtime client 中的 [`lambda-http`](https://github.com/awslabs/aws-lambda-rust-runtime/tree/main/lambda-http) crate 编写函数入口。
- 通过 [API Gateway](https://aws.amazon.com/api-gateway/)、[AppSync](https://aws.amazon.com/pm/appsync)、[VPC Lattice](https://aws.amazon.com/vpc/lattice/) 等 AWS API 服务，将流量路由到 Lambda。
- 如果一个 Lambda 处理 API 的多个端点，可以用 [axum](https://github.com/tokio-rs/axum) crate 在 Lambda 内完成路由。

@@ANCHOR:event-based-task-15-mins-max@@

#### 事件驱动任务：最长 15 分钟

- Lambda 函数由事件触发，并接收事件载荷。例如配置 S3 bucket，在新对象加入时触发函数，函数接收包含新对象信息的载荷并进一步处理。
- 使用 runtime client 中的 [`lambda_runtime`](https://github.com/awslabs/aws-lambda-rust-runtime/tree/main/lambda-runtime) 与 [`lambda_events`](https://github.com/awslabs/aws-lambda-rust-runtime/tree/main/lambda-events) crate 编写函数入口。
- 然后通过 [`lambda invoke` 命令](https://docs.aws.amazon.com/cli/latest/reference/lambda/invoke.html)，或集成的 AWS 触发器，例如 S3 UploadObject 触发器，调用函数。

> 两种情况都必须将 [`tokio`](https://docs.rs/tokio/latest/tokio/) crate 加入项目，因为 Lambda runtime client 用 `tokio` 处理异步调用。

> **问：** 已知函数每次执行平均只用 26MB，低于最小分配量 128MB，为什么还要测试更高的内存配置？
> **答：** [Lambda 的 vCPU 会随内存按比例增加](https://docs.aws.amazon.com/lambda/latest/operatorguide/computing-power.html)，因此增加内存仍可能影响性能。

不过，图中可以看到，为该函数增加内存，也就是增加计算能力，并没有影响性能。[Lambda 执行费用](https://aws.amazon.com/lambda/pricing/)按 GB·秒计算，因此最低内存配置就能以最低价格获得最划算的 Lambda。

![Rust Power Tuner 结果](/images/deploy_1/rig-power-tuner.png)

@@ANCHOR:cold-starts@@

#### 冷启动

[冷启动](https://docs.aws.amazon.com/lambda/latest/operatorguide/execution-environments.html)发生在 Lambda 函数执行环境需要从零启动时，包括建立函数运行所需的计算环境，以及下载函数代码和依赖。冷启动延迟并不影响每次执行，因为环境建立后，同一 Lambda 的后续执行会复用它。

在 Lambda CloudWatch 日志中，如果一次执行需要冷启动，会在执行结束时看到 `Init Duration` 指标。

`rig-entertainer` 的平均冷启动时间是 **90.9ms**：

![Rig 冷启动](/images/deploy_1/rig-coldstarts.png)

245 次执行中有 9 次受冷启动影响，约占 **3.7%**。
