# 服务商与客户端

服务商客户端是接入大模型厂商的入口。它保存厂商配置（凭证、基础 URL、选项）和传输层，并构建可供调用的模型：补全、嵌入、转写、图像和音频模型，具体取决于服务商提供的能力。

开始之前

- 将 `rig` 添加到项目，见[安装](/docs/installation)。
- 导出服务商的 API Key，例如 `OPENAI_API_KEY`，供 `from_env()` 读取。

@@CODE_000@@

客户端及其构建的模型都可以低成本克隆；创建一次后共享使用即可。

@@ANCHOR:provider-clients@@

## 服务商客户端

拥有独立 API 格式的服务商，在 `rig::providers::<name>` 下提供自己的客户端类型：

| 客户端 | 环境变量 | 可构建的模型 |
| --- | --- | --- |
| `openai::OpenAI` | `OPENAI_API_KEY`，可选 `OPENAI_BASE_URL` | 补全、聊天、Responses、嵌入、重排序、转写、图像、音频 |
| `anthropic::Anthropic` | `ANTHROPIC_API_KEY`，可选 `ANTHROPIC_BASE_URL` | 补全 |
| `gemini::Gemini` | `GEMINI_API_KEY` | 补全、嵌入、转写、图像 |
| `cohere::Cohere` | `COHERE_API_KEY` | 补全、嵌入 |
| `ollama::Ollama` | 可选 `OLLAMA_API_BASE_URL`、`OLLAMA_API_KEY` | 补全、原生补全、嵌入 |
| `voyageai::VoyageAi` | `VOYAGE_API_KEY` | 嵌入、重排序 |
| `copilot::Copilot` | `GITHUB_COPILOT_API_KEY`（或 `COPILOT_API_KEY`） | 补全、嵌入 |

每种客户端都有 `from_env()` 和 `new(api_key)`。Ollama 的 `new()` 不需要 Key，连接本地守护进程。图像和音频模型分别需要 `image` 和 `audio` Cargo feature。

@@CODE_001@@

Amazon Bedrock、Google Vertex AI、基于 gRPC 的 Gemini 和本地 Candle 模型位于配套 crate，通过 `bedrock`、`vertexai`、`gemini-grpc`、`candle` feature 启用，见[生态集成](/docs/integrations)。

## 兼容 OpenAI 的厂商

许多厂商提供 OpenAI 格式的 API。它们没有独立客户端类型，而是在模块中提供 `from_env()` 和 `new(api_key)` 函数，返回已配置好厂商基础 URL、凭证变量和协议差异的 `OpenAI` 客户端。

| --- | --- |

| `chatgpt` | `CHATGPT_ACCESS_TOKEN`（ChatGPT 登录 token，不是 API Key） |
| `deepseek` | `DEEPSEEK_API_KEY` |
| `doubleword` | `DOUBLEWORD_API_KEY` |
| `groq` | `GROQ_API_KEY` |

| `hyperbolic` | `HYPERBOLIC_API_KEY` |
| `llamacpp` | `LLAMACPP_API_KEY`、`LLAMACPP_API_BASE_URL` |
| `minimax` | `MINIMAX_API_KEY` |
| `mira` | `MIRA_API_KEY` |
| `mistral` | `MISTRAL_API_KEY` |
| `moonshot` | `MOONSHOT_API_KEY` |

## 选择传输层

默认启用 `reqwest` feature 时，`from_env()` 和 `new(..)` 创建的客户端通过共享 reqwest 客户端发送请求。要配置超时、代理、中间件或测试替身，可将 HTTP 客户端传给配置对象的 `connect`：

@@CODE_004@@

配置的 `connect` 接受任何实现 `rig::http_client::HttpClientExt` 的类型。`DynHttpClient::new(..).with_middleware(..)` 为客户端增加请求和响应钩子，可注入请求头、记录请求体、读取限流响应头。也可以通过 `OpenAIConfig::from_env()?.connect(http)` 将配置直接连接到传输层。

## 客户端构建的模型

| 方法 | 返回值 |
| --- | --- |
| `completion(model)` | 用于[模型生成](/docs/concepts/completion)和 [Agent](/docs/concepts/agent) 的补全模型 |
| `embedding(model, ndims)` | 用于[向量嵌入](/docs/concepts/embeddings)的模型；`ndims` 为 `None` 时使用模型默认维度 |
| `transcription(model)` | 语音转文本模型 |
| `image_generation(model)` | 图像模型，需要 `image` feature |
| `audio_generation(model)` | 文本转语音模型，需要 `audio` feature |

并非每个客户端都有所有方法。不支持的能力会在编译时暴露，而不是等到运行时。后三项见[多媒体](/docs/concepts/media_generation)。
