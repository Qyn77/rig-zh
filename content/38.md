# Anthropic

Anthropic 服务商模块（`rig::providers::anthropic`）通过 Anthropic 的 Messages API 将 Rig 接入 Claude。同一客户端也能访问提供 Anthropic 格式端点的服务商（MiniMax、Moonshot、Xiaomi MiMo、Z.AI）。

@@ANCHOR:capabilities@@

## 支持的能力

| 能力 | 支持情况 | 说明 |
| --- | --- | --- |
| 补全 | 支持 | `client.completion(id)`；`max_tokens` 默认为模型的输出上限 |
| 流式输出 | 支持 | `agent.prompt(p).stream()` 或 `model.stream(request)` |
| 工具 | 支持 | 任意 Rig 工具；通过 `with_strict_tools()` 使用严格工具 schema |
| 结构化输出 | 支持 | 提取器和 `output_schema` |
| 图像和 PDF 输入 | 支持 | 图像与文档内容块 |
| 扩展思考 | 支持 | `GenerationOptions::reasoning`；思考块在轮次之间保留 |
| 提示词缓存 | 支持 | `CacheRetention`，或通过 `with_prompt_caching()` 设置显式断点 |
| 嵌入 | 不支持 | 为 Claude 搭配其他服务商的嵌入模型，例如 [OpenAI](/docs/integrations/model_providers/openai) 或 Voyage AI |

@@ANCHOR:basic-usage@@

## 基本用法

@@CODE_000@@

Anthropic 要求每个请求都带 `max_tokens`。对 Rig 已知的模型，默认值为该模型的输出上限，因此只有需要限制输出时才要在 Agent 构建器或请求上设置 `.max_tokens(n)`。Rig 不认识的模型 ID 没有默认值：需自行设置 `max_tokens`，或通过 `model.wire = model.wire.with_default_max_tokens(n)` 为模型指定默认值。缺少该值的请求会在发送前失败。

@@ANCHOR:configuring-the-client@@

## 配置客户端

@@CODE_001@@

`anthropic-version` 请求头默认为 `ANTHROPIC_VERSION_LATEST`（`2023-06-01`）。Beta 标志通过 `anthropic-beta` 发送；`extension` 模块导出了其选项所需的 beta 常量（`FAST_MODE_BETA`、`TASK_BUDGETS_BETA`、`CONTEXT_MANAGEMENT_BETA`、`MCP_CLIENT_BETA` 等）。

访问其他服务商的 Anthropic 格式端点时，使用对应模块：`minimax::anthropic_from_env()?`、`moonshot::anthropic_from_env()?`、`xiaomimimo::anthropic_from_env()?`、`zai::anthropic_from_env()?`。它们均返回 `Anthropic` 客户端。

@@ANCHOR:models@@

## 模型

模块导出 Claude 模型常量，例如 `anthropic::CLAUDE_OPUS_5_5`、`anthropic::CLAUDE_SONNET_5_5`、`anthropic::CLAUDE_FABLE_5_1` 和 `anthropic::CLAUDE_HAIKU_4_5`。也可以直接使用任意模型 ID 字符串。`client.list_models().await?` 列出该密钥可用的模型；`client.verify().await?` 检查密钥。

@@ANCHOR:extended-thinking@@

## 扩展思考

通过与服务商无关的 `reasoning` 选项设置推理。Rig 将其转换为模型支持的形式：较新模型使用带强度等级的自适应思考，较旧模型使用思考 token 预算。

@@CODE_002@@

Claude 不提供 `Effort::Minimal`；如果模型不支持所请求的形式，请求会以 `ProviderError::UnsupportedOption` 失败（可使用 `.on_unsupported(OnUnsupported::Ignore)` 改为跳过）。思考块和已隐藏的思考块以推理内容返回，并在下一轮连同签名一起回传，因此多轮工具调用可以继续正常工作。

@@ANCHOR:prompt-caching@@

## 提示词缓存

Anthropic 有两种缓存方式。

**使用 `CacheRetention` 自动缓存。** 设置 `cache` 会发送顶层 `cache_control` 标记，Anthropic 会缓存提示词，直到最后一个可缓存内容块。`Short` 表示五分钟缓存，`Long` 表示一小时缓存：

@@CODE_003@@

**在模型上显式设置断点。** `with_prompt_caching()` 在系统提示词、最后一个工具定义和对话最后一个内容块上设置 `cache_control` 断点。`with_static_prefix_cache_ttl` 可以让工具和系统提示词的缓存时间长于对话尾部：

@@CODE_004@@

一小时标记必须位于五分钟标记之前，因此在 `CacheRetention::Long` 下使用五分钟静态前缀会在构建请求时失败。每个缓存前缀都必须达到模型要求的最小可缓存长度。

缓存活动体现在响应的 `Usage` 中，这些字段由各服务商统一填写：

| 字段 | 含义 |
| --- | --- |
| `input_tokens` | 全部输入 token，包括缓存读取和写入 |
| `cached_input_tokens` | `input_tokens` 中从缓存读取的部分 |
| `cache_creation_input_tokens` | `input_tokens` 中写入缓存的部分 |
| `output_tokens` | 全部输出 token，包括思考 |

按缓存有效期划分的写入明细（五分钟与一小时）位于下文的回复扩展字段中。

@@ANCHOR:anthropic-only-options-and-reply-fields@@

## Anthropic 专有选项与回复字段

仅 Anthropic 自家 API 接受的字段在 `anthropic::extension::AnthropicOptions` 中提供类型定义：`top_k`、`metadata_user_id`、`inference_geo`、`speed`（快速模式）、`task_budget`、`fallbacks`、`container`（技能）、`context_management` 和 `mcp_server`（MCP 连接器）。其中一些要求客户端带 beta 标志，各字段都有说明。这些选项只会发送给 Anthropic 本身，不会发送给 Anthropic 格式网关。

@@CODE_005@@

Anthropic 专有回复字段（`stop_reason`、`stop_details`、`cache_creation`、`service_tier`、`inference_geo`、`speed`、服务端工具用量、`container`、`fallback_model`）通过 `extras::<AnthropicExt>()` 读取：

@@CODE_006@@

`ServiceTier::Auto` 和 `ServiceTier::Default` 分别映射为 Anthropic 的 `auto` 和 `standard_only` 等级；Anthropic 没有 flex 或仅优先级服务等级。

@@ANCHOR:tools@@

## 工具

Claude 可以调用你注册到 Agent 上的任意工具。Rig 将工具定义转换为 Anthropic 格式，并将 `tool_use` 块解析回 Rig 工具调用。`model.wire.with_strict_tools()` 要求 Anthropic 让每次工具调用严格符合 schema。见[工具](/docs/concepts/tools)。
