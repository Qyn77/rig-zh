# 流式输出

流式输出让你在响应生成过程中就处理它，无需等待全部完成。它能让聊天 UI 更及时，也能在模型编写工具调用时就展示调用内容。Rig 支持两个层次的流式输出：整个 **Agent 运行**，包含每个模型轮次、工具调用和结果；以及不带 Agent 循环的单次**模型调用**。

开始之前

- 先构建基本的 [Agent](/docs/concepts/agent)：流式运行使用同一个 Agent 和相同的循环。
- 设置 `OPENAI_API_KEY`，确保 `OpenAI::from_env()` 成功。
- 在 `Cargo.toml` 添加 `futures`，以使用 `StreamExt::next`。

## 流会产生什么

`MultiTurnStreamItem` 包含以下变体。它标记了 `#[non_exhaustive]`，因此匹配时要保留 `_ => {}` 分支。

| 变体 | 到达时机 |
| --- | --- |
| `StreamAssistantItem(Item<StreamEvent>)` | 模型的实时输出：文本、推理和工具调用片段，见下文。 |
| `ToolCall { tool_call }` | 工具调用已提交到运行历史；它可能被跳过或重放，不能据此认定工具实际执行。 |
| `ToolExecutionCommitted { tool_call }` | Rig 实际执行的工具调用，包含钩子应用的改写。在整批调用完成后，随结果一起到达。 |
| `ToolResult { tool_result }` | 发回模型的结果。`tool_result.call` 是它所回答的调用 ID。 |
| `CompletionCall(CompletionCall)` | 一次模型调用结束，携带该调用的 `usage`、`finish_reason` 和响应 ID。 |
| `ModelTurnRetried { turn }` | 钩子拒绝了已完成的轮次并要求重试。应丢弃此前为 `turn` 展示的流式文本。 |
| `FinalResponse(PromptResponse)` | 运行完成。它与 `.await` 返回的 `PromptResponse` 相同，提供 `output()`、`usage()`、`messages` 和 `completion_calls()`。 |

流的元素类型是 `Result<MultiTurnStreamItem, PromptError>`。`Err` 一定是最后一个元素：运行以与 `.await` 相同的 [`PromptError`](/docs/concepts/error_handling) 失败，之后不会再有事件。

@@ANCHOR:model-output-streamevent@@

### 模型输出：`StreamEvent`

`StreamAssistantItem` 包装一个 [`Item`](https://docs.rs/rig/0.46.0/rig/streaming/enum.Item.html)：它可能是 `Item::Event(StreamEvent)`，也可能是 `Item::Unknown(..)`，即 Rig 尚未建模的服务商数据，可以安全忽略。响应由带编号的**部分**（part）组成，例如文本块、推理块或单个工具调用。每个部分依次流出开始事件、若干片段和结束事件：

| `StreamEvent` | 含义 |
| --- | --- |
| `Start { part, kind, name }` | 一个部分开始。`kind` 为 `PartKind`，例如 `Text`、`Reasoning`、`ToolCall` 等；工具调用时，`name` 为工具名。 |
| `Text { part, text }` | 文本片段。 |
| `Reasoning { part, text }` | 推理片段，用于支持流式思考内容的模型。 |
| `Arguments { part, json }` | 工具调用参数 JSON 的片段。 |
| `End { part, content }` | 该部分完成。`content` 是完整的 `AssistantContent`；对于工具调用，它是带 ID 的完整 `ToolCall`。 |

工具调用会逐段输出参数，因此模型仍在生成时，UI 就能显示较长的参数，例如正在写入的文件或很长的查询。将同一次调用的片段拼接起来，就是它的参数 JSON。`rig::streaming::parse_partial_arguments(&so_far)` 会尽力将尚未完整的前缀解析为 JSON 对象：

@@ANCHOR:practical-notes@@

## 实用说明

- **在循环中处理错误。** 创建流本身不会失败；所有失败都会作为 `Err` 元素到达，而且它始终是最后一个元素。
- **丢弃被重试轮次的内容。** 如果使用了重试轮次的钩子，在收到 `ModelTurnRetried` 时重置该轮已经展示的文本。
- 需要最终、已校验的调用时，**从 `End` 或 `ToolCall` 读取工具调用**，不要依赖自行拼接的片段。
