# 结构化输出

Rig 可以返回 Rust 值，而不只是字符串。你指定目标类型，Rig 将它的 JSON Schema 发给模型，再把回复反序列化为该类型。有两种方式：

- **`Extractor`** 将一段文本转换成 `T`。当整个任务就是提取信息时，使用它。
- **`agent.prompt_typed::<T>(..)`** 执行普通 Agent 提问，支持工具、历史和钩子，再将最终答案解析为 `T`。结构化输出只是较大 Agent 工作流中的一步时，使用它。

开始之前

- 安装 `rig` 并设置模型服务商 API Key，参见[模型服务商客户端](/docs/concepts/provider_clients)。
- 在 `Cargo.toml` 添加 `schemars = "1"`；目标类型需要派生它的 `JsonSchema`。
- 提取器建立在 Agent 和工具之上，建议先浏览 [Agents](/docs/concepts/agent) 和[工具](/docs/concepts/tools)。

## 工作原理

提取器是一个带固定系统提示词和单个 `submit` 工具的 [Agent](/docs/concepts/agent)，工具参数就是目标类型的 JSON Schema。每次提取只执行一个模型轮次，并把工具选择设为必需，因此模型必须调用 `submit`；Rig 将调用参数反序列化为 `T`。如果模型没有调用工具，而是直接返回了符合 `T` 的普通 JSON，Rig 也会接受。

## 配置提取器

`ExtractorBuilder` 暴露了适合提取任务的 Agent 设置：

@@CODE_002@@

- `append_preamble` 在内置提取系统提示词之后添加指令。内置提示词会要求模型调用 `submit`，不能替换。
- `context` 添加静态文档；`dynamic_context(n, index)` 在每次提取时从[向量索引](/docs/concepts/rag)检索 `n` 个文档。
- `retries(n)` 在某次尝试失败后，最多再尝试 `n` 次。请求出错、模型没有提交任何内容，或提交的 JSON 不符合 `T`，都属于尝试失败。
- `additional_params` 和 `add_hook` 的行为与 `AgentBuilder` 相同。

`extract(..)` 返回的运行可以在等待前继续调整，例如使用 `.history(&messages)` 从对话中提取，或用 `.retries(n)` 为本次调用设置重试次数。

## 错误处理

提取和类型化提问失败时，返回 [`StructuredOutputError`](https://docs.rs/rig/0.46.0/rig/completion/enum.StructuredOutputError.html)：

- `EmptyResponse`：模型没有生成可解析内容；对提取器而言，就是没有调用 `submit`。
- `Deserialization { output, error }`：模型 JSON 不符合 `T`。`output` 保存原始文本。
- `Prompt(PromptError)`：运行本身失败，例如服务商错误或轮数预算耗尽。参见[错误处理](/docs/concepts/error_handling)。

注意
