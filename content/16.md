# 记忆 Memory

记忆是 Agent 重用当前对话之前的信息，以及跨对话信息的能力。没有记忆，每次提问都从头开始：用户先问“我的订单是什么状态？”，再说“取消它”，模型就不知道“它”指什么。Rig 同时支持两种做法：接入对话记忆后端，由它替你加载和保存历史；或自行维护 `Vec<Message>`，精确决定模型看到什么。

开始之前

- 先构建并调用一个基本 Agent，参见 [Agents](/docs/concepts/agent)。
- 按照[模型服务商客户端](/docs/concepts/provider_clients)页面设置 API Key，例如 `OPENAI_API_KEY`。

记忆有两层：

- **对话历史**（短期）：当前对话的消息，每轮重新发送给模型，并限制其大小，确保能放进上下文窗口。
- **长期记忆**：超出单次会话生命周期的事实、观察和用户资料，通常保存在数据库或向量存储中。

记忆与其他提问 API 的关系：

- 用 `.conversation("...")` 为每次请求设置 ID，或用 `AgentBuilder::conversation("...")` 为 Agent 设置默认 ID。未指定时使用 Agent 名称，匿名 Agent 默认日志名为 `agent`；共享存储的不同用户应使用不同日志名。
- 用 `.history(...)` 显式传入历史，或调用 `agent.chat(...)`，都会**绕过记忆**：既不加载，也不保存。
- `.without_memory()` 为一次请求关闭记忆。
- 加载失败时，运行会在任何模型调用发生之前返回 `PromptError::Memory`。保存失败也返回 `Err(PromptError::Memory { error, response })`，其中 `response: Some(...)` 保留已完成响应；不能把它当作保存成功。

## 长期记忆

有边界的历史让一次对话保持良好状态，但很多应用还需要跨会话保留记忆。常见类型包括：

- **对话观察**：已经做出的决定、待解决的问题、明显感兴趣的话题。
- **用户资料**：用户的稳定信息，例如明确表达的偏好或位置。应与对话历史分开存储，逐步更新，并在依赖这些信息前重新核实。
- **有依据的事实**：会话中收集的可验证数据，例如检索文档、计算结果和 API 响应，连同来源与时间一起保存。

三者的处理机制相同。重要交流结束后，用[提取器](/docs/concepts/extractors)或普通提问提炼重要内容，再保存。新对话开始时，获取最相关的条目，将其加入系统提示词或开场消息。需要语义查找时，将记忆嵌入到向量存储，再用 [`dynamic_context`](/docs/concepts/rag) 检索。宿主可在一次成功运行后或显式压缩之前，把需要保留的信息写入这类存储。
