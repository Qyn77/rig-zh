# Testing

A Rig agent takes any model, so in tests you can give it a **mock** model and
check your agent’s behaviour without calling a provider. Tests run offline, cost
nothing, and are deterministic. The mocks live in `rig::test_utils`, behind the
`test-utils` feature.

Before you start

## Mock a model response

`MockCompletionModel::text(...)` returns a model that replies once with the
given text. Build a normal agent on top of it and prompt as usual; no API key
is needed.

@@CODE_002@@

Each scripted turn is used once. If the agent calls the model more often than
you scripted, the extra call fails with a provider error, so a test can’t
silently pass on a repeated answer.

@@ANCHOR:script-a-multi-turn-tool-loop@@

## Script a multi-turn tool loop

Real agents loop: the model asks for a tool, Rig runs it, and the model answers
with the result. Script each model turn with `MockTurn`: `MockTurn::tool_call(id, name, args)`
for a tool request and `MockTurn::text(...)` for the final answer. Clones of a
`MockCompletionModel` share their state, so keep one to inspect afterwards.

@@CODE_003@@

`MockTurn::error(...)` scripts a provider failure, which is how you test your
error handling and retries. For streaming agents, script the chunks with
`MockCompletionModel::from_stream_turns` and `MockStreamEvent`.

@@ANCHOR:assert-what-the-model-received@@

## Assert what the model received

The mock records every request it was sent. Use `requests()` to check the exact
request your agent built: system prompt, history, tools, and context documents.

## Replaying recorded runs

Mocks are best for the logic you own. To test against what a real model
actually said, record a live run once and replay it in CI. See
[Recording & Replay](/docs/concepts/recording).

Note

Keep mock-based tests about your own code: tool wiring, prompt construction,
retrieval, and error handling. Whether a real model gives good answers is a
question for recorded runs and manual review, not for scripted mocks.
