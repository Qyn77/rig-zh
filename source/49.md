# FAQ

Short answers to common questions. For anything conceptual, the linked pages go deeper.

@@ANCHOR:what-is-rig@@

## What is Rig?

Rig is an open-source Rust library for building applications powered by large language models: one
API across providers, plus higher-level building blocks like agents, tools, RAG, and structured
extraction. Start with the [Introduction](/docs) and the [Quickstart](/docs/quickstart).

@@ANCHOR:should-i-depend-on-rig-rig-core-or-rig-agent@@

## Should I depend on `rig`, `rig-core`, or `rig-agent`?

Depend on `rig`. It re-exports `rig-core` (provider, model, tool, and vector-store contracts) and
`rig-agent` (the agent runtime, on by default), and exposes integrations behind cargo features.
Depend on `rig-core` directly only if you want the provider contracts without the agent runtime or
the facade’s integrations. See [Architecture](/docs/architecture).

@@ANCHOR:which-model-providers-does-rig-support@@

## Which model providers does Rig support?

More than 20 behind one API, including OpenAI, Anthropic, Google Gemini, Cohere, Mistral, xAI,
DeepSeek, Groq, OpenRouter, Perplexity, Together, Azure OpenAI, Hugging Face, and Ollama, plus
Amazon Bedrock and Google Vertex AI through feature-gated companion crates. See
[Providers & Clients](/docs/concepts/provider_clients) and
[Model Providers](/docs/integrations/model_providers).

@@ANCHOR:can-i-run-local-or-self-hosted-models@@

## Can I run local or self-hosted models?

Yes. Use the Ollama or llama.cpp clients for a local server, point `OpenAIConfig::with_base_url` at
any OpenAI-compatible endpoint, or enable the `candle` feature to run supported models in-process.
See [Providers & Clients](/docs/concepts/provider_clients#any-other-openai-compatible-server).

@@ANCHOR:do-i-have-to-use-tokio@@

## Do I have to use Tokio?

The examples use `#[tokio::main]`, but Rig doesn’t require Tokio. The bundled HTTP transport brings
what it needs, and an agent run is a plain future you can drive on any executor.

@@ANCHOR:does-rig-work-in-the-browser@@

## Does Rig work in the browser?

Yes. Rig builds for `wasm32-unknown-unknown` with no extra features. MCP tools and the bundled
websocket backend are native-only, and WASI targets are not supported. See
[Installation](/docs/installation#webassembly).

@@ANCHOR:does-rig-support-fine-tuning@@

## Does Rig support fine-tuning?

No. Rig focuses on inference and orchestration, not training. Fine-tune with your provider’s tooling,
then use the resulting model id with Rig like any other model.

@@ANCHOR:how-do-i-continue-a-conversation@@

## How do I continue a conversation?

Pass the earlier messages with `.history(&history)` on a prompt, then append the run’s new messages:
`history.extend(response.messages)`. For conversations that load and save themselves, attach a
memory backend. See [Agents](/docs/concepts/agent) and [Memory](/docs/concepts/memory).

@@ANCHOR:how-do-i-set-reasoning-effort-prompt-caching-or-other-provider-settings@@

## How do I set reasoning effort, prompt caching, or other provider settings?

Common settings are typed and portable: `.reasoning(Effort::High)`, `.cache(CacheRetention::Long)`,
`.service_tier(..)`, `.seed(..)`, and others on a `CompletionRequest`, an `AgentBuilder`, or a single
run. Provider-only settings go through typed options from `rig::providers::<name>::extension` with
`.provider_option(..)`, and `additional_params` still takes raw JSON. See
[Completions](/docs/concepts/completion#generation-options).

@@ANCHOR:how-does-rig-handle-rate-limits-and-retries@@

## How does Rig handle rate limits and retries?

Rig doesn’t retry provider calls on its own. `ProviderError::is_retryable()` tells you whether a
failure is transient, so you can retry with backoff around a call; you can also retry at the HTTP
layer with a `reqwest-middleware` client passed to `with_http`, or retry a model turn from an agent
hook. Typed extraction has its own `.retries(n)` for answers that fail to parse. See
[Error Handling](/docs/concepts/error_handling).

@@ANCHOR:can-i-use-rig-in-a-web-service@@

## Can I use Rig in a web service?

Yes. Rig is async, so it fits web frameworks like Axum and Actix as well as serverless targets. See
the [Guides](/docs/guides), including the AWS Lambda deploy walkthroughs.

@@ANCHOR:can-i-test-without-calling-a-real-model@@

## Can I test without calling a real model?

Yes. The `test-utils` feature provides mock models you can script turn by turn, and the `cassette`
feature records real runs and replays them offline. See [Testing](/docs/concepts/testing).

@@ANCHOR:how-does-rig-compare-to-other-llm-frameworks@@

## How does Rig compare to other LLM frameworks?

Rig gives you the building blocks you’d expect (agents, tools, RAG, structured extraction) with
Rust’s performance and type safety and a single API across providers. See
[Architecture](/docs/architecture) for how the pieces fit together.
