# Local Models

Rig can run entirely on your own hardware. There are two kinds of local setup:

- **A local server** that Rig talks to over HTTP: [Ollama](#ollama) or [llama.cpp](#llamacpp). Both are built into `rig` and need no extra feature.
- **In-process inference**, with no server at all: [Candle](#candle) for completions and [fastembed](#local-embeddings-with-fastembed) for embeddings. Both are companion crates behind a feature on `rig`.

Whichever you pick, the model plugs into `AgentBuilder`, `EmbeddingsBuilder` and the vector stores like any hosted model.

## Ollama

`Ollama::new()` talks to the daemon at `http://localhost:11434` with no authentication. `Ollama::from_env()` reads the optional `OLLAMA_API_BASE_URL` and `OLLAMA_API_KEY` for a remote or secured daemon.

Ollama serves two chat APIs, and Rig has a model for each:

- `client.completion(id)` uses Ollama’s OpenAI-compatible `/v1/chat/completions`.
- `client.native_completion(id)` uses Ollama’s native `/api/chat`. Only this route sends model parameters such as `num_ctx`, and it maps the `reasoning` option to Ollama’s `think`.

## Candle

`rig::candle` (feature `candle`) runs models in your process on the CPU with [Candle](https://github.com/huggingface/candle). You load the model files yourself and hand Rig the bytes; the crate does no filesystem or network access.

@@CODE_005@@

@@CODE_006@@

Only validated checkpoints load; anything else is rejected rather than guessed at:

- **Llama 3 instruct**: one unsharded safetensors checkpoint.
- **SmolLM2-360M-Instruct**: Q4\_K\_M GGUF. Small enough to run in the browser through WASM.
- **Qwen3-4B**: the official Q4\_K\_M GGUF, with native tool calling. Native targets only.

Use `CandleModel::from_gguf(data)?` for GGUF files. GGUF models currently have a 4096-token context. Candle’s local metrics (prompt and generated tokens, prefill time, time to first token, tokens per second) are typed reply extras, read with `response.extras::<rig::candle::extension::CandleExt>()`.

`rig::candle::pose` adds YOLOv8 pose estimation (`CandlePoseModel`), which streams the poses found in each frame of a sequence of images.

The Rig repository has three runnable examples: [`candle_local`](https://github.com/0xPlaygrounds/rig/tree/v0.44.0/examples/candle_local) streams a completion from a local GGUF model and prints Candle’s metrics, [`candle_pose`](https://github.com/0xPlaygrounds/rig/tree/v0.44.0/examples/candle_pose) estimates poses in images, and [`candle_wasm_chat`](https://github.com/0xPlaygrounds/rig/tree/v0.44.0/examples/candle_wasm_chat) runs SmolLM2 and a Rig agent inside a browser Web Worker, so chat messages never leave the page.

## Local embeddings with fastembed

`rig::fastembed` (feature `fastembed`) runs [fastembed](https://github.com/Anush008/fastembed-rs) embedding models in your process. The `fastembed` feature downloads models from Hugging Face and ONNX Runtime binaries on first use; `fastembed-hf-hub` and `fastembed-ort-download-binaries` enable those parts separately. It is native-only.

@@CODE_008@@

Pair it with Ollama, llama.cpp or Candle for a pipeline where neither documents nor prompts leave the machine.
